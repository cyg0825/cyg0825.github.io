06-界面骨架与样式

发表于2026-11-05|更新于2026-11-07|学习连连看
|浏览量:

这一篇的位置

前五篇讲的都是数据与算法：棋盘的形状、发牌、连线判定、死局与重排、格子尺寸。这一篇讲承载它们的那层：Link/index.html 的骨架和 Link/style.css 的样式。这两份文件都很短，却决定了前面所有计算能不能被看见、被点着。

这一篇的顺序是先骨架后样式：先把 HTML 里每个块是什么、为什么在这儿讲清，再按样式文件的书写顺序讲它做了哪几件事。代码与数据怎么把这些空壳填满，归第七篇。

篇 讲什么
01 结构与数据形状 文件分工、棋盘的真实形状、关卡表
02 随机数与发牌 自带随机数发生器、洗牌、成对发牌
03 连线判定 拐弯不超过两次怎么判、折线怎么回溯出来
04 死局与自动重排 有没有可连的一步、重排怎么保证不越排越死
05 布局自适应 格子尺寸怎么算、窗口变化怎么跟
06 界面骨架与样式 HTML 与 CSS 逐行
07 点击、计分与存档 点击状态机、计时与分数、本地存档、音乐

骨架：一个文件装两个界面

  • 第 1 行 <!DOCTYPE html>：声明这是标准模式页面。浏览器对同一份 CSS 在标准模式和怪异模式下算法不同，比如盒模型和图片基线对齐，少了这一行，第五篇那些像素计算会整体偏移。
  • 第 2 到 9 行是一个完整页面的头：<html> 带语言、<head> 里依次是字符集、视口、图标、标题、样式表，第 9 行 </head> 之后才是 <body>。这一页自己就是一个完整的 HTML 文档，不依赖任何外部模板。
  • lang="zh-CN" 告诉浏览器和读屏软件正文语言，影响断词、朗读和字体回退。
  • charset="UTF-8" 必须放在 <head> 很靠前的位置：浏览器在读到它之前，字节流是按默认编码解释的，放晚了中文会先乱一下。
  • viewport 三个值：width=device-width 让页面宽度等于设备宽度（不加就按 980 像素排版再缩小，手机上字会糊成一团）、initial-scale=1 是初始缩放比例、viewport-fit=cover 让页面铺到刘海和圆角区域，配合样式里的 env(safe-area-inset-*) 使用。
  • 样式表用相对路径 style.css，脚本同理用 script.js。相对路径让这三份文件可以整体挪到任何目录下都能跑，第五篇和第七篇里那些像素计算也不依赖根路径。图片路径 img/image0.jpg 同样是相对写法。

<body> 里只有六块，按顺序是：

顶栏三块：站名、状态条、右侧图标按钮。

  • #hud 带着 hidden：初始在首页，状态条不该占位。hidden 是 HTML 布尔属性，写上去就是「藏起来」，样式里第 29 行还专门给它兜底。
  • 状态条里四个 <b> 都带 id，是第七篇 syncHud 的写入目标。数字用 <b> 而不是 <span>，是为了让样式能只挑「数字」加粗，前面的说明文字保持细体。font-variant-numeric:tabular-nums（样式第 32 行）让每个数字占同样宽度，倒计时跳动时整行不会左右晃。
  • 两个图标按钮的图标是内联 SVG：viewBox="0 0 24 24" 是这套图标的坐标系，<path d="..."> 是形状描述。内联而不是 <img> 的原因在样式里：fill:currentColor 让图标颜色跟着按钮文字色走，悬停变色时图标一起变。
  • aria-label 给读屏软件一个名字（按钮里只有图形没有文字）；aria-hidden="true" 让 SVG 本身对读屏不可见，避免念出一串路径数据。
  • #bMusic 里那条 <line class="slash"> 是「静音斜杠」，默认 display:none，音乐关掉时加上 off 类才出现（样式第 41 到 42 行）。

<main> 里两个 <section>，一个首页、一个对局，靠 hidden 互斥切换。这是整页唯一的「界面切换」机制：没有路由、没有第二个 HTML 文件，renderHome 和 start 各自改这四个 hidden。

  • #levels 是个空容器。二十颗关卡按钮由 renderHome 现场造出来（第七篇），因为按钮上的说明行要读关卡表和存档，写在 HTML 里就得手动同步两处。
  • .sum 那行汇总同样只留 id 空位。
  • #game 里三块：进度条、棋盘区、按钮区。#act 带 hidden 的原因是首页时它本来不可见（父级 #game 就藏着），进对局后由 toolset(true) 显式打开，第五篇的 keepBottom 读的就是它的 hidden 状态和 offsetHeight。
  • 棋盘那一行是本页唯一的四层嵌套：#stage 管滚动，#board 管尺寸与背景，#line 是画折线的 SVG 层，#tiles 是装图块的层。后两层都是 position:absolute; inset:0，叠在同一个盒子里。
  • SVG 写在图块层之前，所以折线画在图块之下。路径只走空格，端点落在图块底下被压住一点，视觉上仍然完整，好处是线永远不会盖住图案。
  • 提示与重排按钮里的 <span class="n"> 是剩余次数，syncTools 写它并据此禁用按钮（第四篇）。
  • #toast 是底部浮出的短句，空标签，内容每次由 toast() 写进去。
  • #mask 是通关与失败用的遮罩弹窗：外层铺满屏幕并居中，内层 .dlg 是那张卡。标题、正文、两个按钮的文字和点击函数都由 dialog() 六个参数填（第四篇出现过它的调用）。两个按钮都留空，因为按钮文案随场景变：通关时是「下一关」和「首页」，最后一关变成「首页」单按钮，时间到变成「再来一次」和「首页」。
  • <audio preload="none">：不预载音频。浏览器对自动播放有限制，没交互就下载音频是浪费；真正要播时由 ensureMusic 现场设 src 并 play()，失败就提示「点一下屏幕才能出声」（第七篇）。
  • <script> 放在 </body> 之前：脚本里第一件事就是 $('...') 取元素，元素还没解析出来就取到 null。放末尾是最省事的解决办法，不用等任何事件。

样式第一层：令牌与深浅色

:root 选中整个文档根，写在这里的 --名字 是自定义属性，也就是「令牌」：一个值起个名，后面到处用 var(--名字) 取。这九个名字各管一件事：--bg1/--bg2 页面渐变两端、--ink 主文字、--ink2 次要文字、--card 卡片底、--line 描边、--accent/--accent2 主色与主色的深一档、--danger 时间告急、--shadow 卡片投影。

深色模式的全部实现就是这七行：prefers-color-scheme:dark 是系统设置查询，命中时把同名令牌换成一套深色值。整份样式文件里除了这两块之外没有任何一处再判断深浅，因为所有规则都只写 var(--token)。换一套颜色不需要动任何一条布局规则，这是令牌写法唯一但足够的回报。

--ink:rgba(255,255,255,.9) 用半透明白而不是纯白：纯白在深底上对比过强，长时间看字会发虚，降到九成白柔和一些。--shadow 在深色下换成黑色投影，浅色下是带蓝灰的阴影，同一个变量名，两种物理含义。

  • *{box-sizing:border-box}：把所有元素的盒模型改成「宽度含内边距和边框」。默认写法是内容宽度再加内边距，算尺寸时要减来减去；改成 border-box 之后 width:34px 就是最终占位 34 像素。第五篇里 cell 乘出来的尺寸和图块的 width/height 能直接对上，靠的是这一行。
  • html,body{height:100%}：给视口高度一个可参照的锚，#mask 那种 position:fixed; inset:0 不依赖它，但页面在内容很少时也能铺满渐变背景。
  • margin:0：浏览器给 body 默认 8 像素外边距，不清掉会在四周留一圈白，#stage 的可用宽度也会跟着算错。
  • linear-gradient(160deg,...)：160 度方向的线性渐变，两个端点是那两个背景令牌。
  • font 是简写，一次给出字号、行高和字体列表。15px/1.6 是 15 像素字号配 1.6 倍行高。字体列表从系统字体族开始（苹果系、Google 系），中文依次回退到苹方、冬青黑体、微软雅黑，最后 sans-serif 兜底。列表里带空格的名字要加引号。
  • -webkit-text-size-adjust:100%：关掉移动端「根据内容自动放大字号」的行为。这个行为会破坏第五篇算出来的格子与文字比例，页面里已经有 viewport 声明，不需要再放大一次。

顶栏：粘住、模糊、避开刘海

  • display:flex 让三块水平排开，align-items:center 垂直居中，gap:10px 是块间距（比用外边距干净：最后一块后面不会多出空隙）。
  • flex-wrap:wrap：窄屏放不下时允许折行。顶栏里 #tools 用 margin-left:auto 贴右（第 33 行），一旦折行，图标块会另起一行仍然贴右，站名和状态条在上面一行，不会出现文字压在图标上的重叠。
  • padding 的左右用 max(16px, env(safe-area-inset-left))：env() 取系统安全区距离，横屏有刘海的设备上是二三十像素。max 的意思是「至少 16 像素，刘海更宽就按刘海来」，两头都不会贴边。
  • position:sticky; top:0：粘顶。页面在棋盘超出时向下滚，顶栏留在原位，倒计时和分数始终可见。z-index:5 保证它盖在滚动内容之上。
  • color-mix(in srgb, var(--bg2) 88%, transparent)：把背景色和透明色按 88% 混，得到一个半透明底。配 backdrop-filter:blur(6px) 就是毛玻璃：底下滚过去的图块被模糊成一片，顶栏文字仍然清晰。两者要一起用，半透明不配模糊会透出杂乱的图块边缘。

[hidden]{display:none !important} 这一行值得单独讲。属性选择器 [hidden] 的权重很低，而后面很多规则直接给元素写了 display：#hud 是 flex、#tools 是 flex、#act 是 flex。这些带 id 的规则权重远高于 [hidden]，一旦元素被藏起来的同时又命中了某条 display:flex，hidden 属性就失效了，元素照样显示。!important 把这条规则的优先级顶到最高，保证「写着 hidden 就一定不显示」。这是这套界面用 hidden 当唯一切换手段时必须补的一块地基。

font-variant-numeric:tabular-nums 是等宽数字：每个数字占同一格宽，01:29 变成 01:28 时整行宽度不变，倒计时不会左右抖。

按钮：一套基础样式，两种形状

  • font:inherit：按钮默认不吃页面字体，浏览器会给一套自己的字体，inherit 让它跟随 body。
  • min-height:34px：可点区域的高度下限。手指点击的可靠尺寸在 40 上下，34 是「文字按钮」的下限，图标按钮另用 min-width:40px 撑。
  • touch-action:manipulation：告诉浏览器这块区域只做点击和滚动，不用做双击缩放，移动端因此省掉约 300 毫秒的点击判定延迟。图块上也有这一句（第 70 行）。
  • #tools button.ico 只给顶栏那两个图标按钮改形状：内边距换成横向、最小宽 40、用 flex 把 SVG 居中。
  • fill:currentColor 让 SVG 的填充色取按钮的文字色，于是悬停那一句改 color 时图标跟着变，不用单独写图标的悬停规则。
  • 静音斜杠两条规则：默认 display:none，#bMusic 带上 off 类时显示。stroke:currentColor 让斜杠颜色同样跟文字色，fill:none 是因为 <line> 是描边图形。
  • button:hover:not(:disabled)：:not(:disabled) 挡掉禁用按钮。第四篇里提示与重排次数用完会置灰，置灰状态下再给悬停色会误导「还能按」。
  • button .n 是按钮里的剩余次数，用次要文字色压暗，让「提示」两个字比数字更抢眼。

首页：一行流式网格

  • main 的 max-width:1240px; margin:0 auto 是全站内容宽度上限与水平居中，第五篇 stageBox 里那个 1240 就是照着这一行写的：JS 要算可用宽度，样式里已经限了，两边必须同一个数。
  • padding 的第三项 calc(40px + env(safe-area-inset-bottom))：底部留白再加手机横条（home indicator）的高度，最后一行按钮不会被系统条压住。
  • #levels 是本页唯一的网格。repeat(auto-fill,minmax(150px,1fr)) 读作「每列至少 150 像素、能放几列放几列、放不下的余量按比例摊给各列」。列数由容器宽度自己算，不写断点：宽屏七列、平板五列、手机两列，同一行代码。写死列数会在中间尺寸出现一边空一大块的情况。
  • .lv 是关卡卡片：text-align:left 是因为按钮元素默认文字居中，卡片里两行文字左对齐才读得顺。
  • .lv .d 那行说明文字（6×4 · 6 种图 · 01:30 · 最高 541）用 13 像素和次要色，和上面的关卡名拉开层级。
  • .lv:disabled 是未解锁的关卡：半透明、去投影、光标回到默认。第七篇的 renderHome 用 n<=save.max+1 决定 disabled，样式这边只负责让它看起来不能按。
  • .sum 是首页底部那行汇总，数字同样用等宽数字。

两张图里没有任何一条针对手机写的布局规则，差别全部来自那行 auto-fill。

对局区：三层叠起来的棋盘

  • 进度条是「外框加内条」两层：外框 6 像素高、圆角、overflow:hidden 把内条的两端裁成圆头；内条 height:100% 跟随，宽度由 JS 按剩余时间百分比写（第七篇 syncHud，第 264 到 270 行）。transition:width .2s 让每 100 毫秒一次的写入看起来是连续滑动。
  • #bar.low 在剩余 10 秒以内换成 --danger，是 JS 加类、样式给颜色的分工。
  • #stage 三条滚动相关设定在第五篇讲过用途：装不下时区块内部滚动、移动端惯性滚动、横向滚到头不回弹带动整页。
  • #act 是棋盘下三个按钮，justify-content:center 居中、flex-wrap:wrap 让窄屏折行。第五篇的 keepBottom() 读它的 offsetHeight，所以折成两行时预留高度会自动变大，不需要代码知道它现在几行。
  • #board 的 position:relative 是给里面两层绝对定位当参照：inset:0 的含义是「贴着最近那个定位祖先的四条边」，没有这句 relative，图块会相对整个页面定位，坐标全错。margin:0 auto 让棋盘在区块里水平居中。底色用 color-mix 把卡片色和透明混到 55%，得到一块比页面略亮又透出渐变的板面。
  • #tiles 的三条不可选：user-select:none 禁止连点选中文字（图块里没有文字，但双击会触发选择逻辑），-webkit-touch-callout:none 关掉 iOS 长按弹出的菜单，否则按住图块会弹出「拷贝/查询」浮层，打断连点。
  • #line 的 pointer-events:none 是第三篇画折线那节的另一半：SVG 铺满整个棋盘，不关掉事件就会挡住下面的图块，线一画出来那块区域就点不动。overflow:visible 允许折线画到盒子边缘之外不被裁。

图块：一个元素，五种状态

  • .tile 是第五篇 tileEl 造出来的那个 div，position:absolute 配合内联的 left、top、width、height 落到具体格子上。它自己不带任何可见外观（padding:0; border:0; background:none），外观全在内层 span 上。
  • 分成两层的原因：外层负责「在哪个格子、多大」，由 JS 按数据算；内层负责「长什么样、怎么动」，由样式负责。内缩 6 像素（calc(100% - 6px)）加上 flex 居中，让相邻图块之间留出缝，格子边长再小也不会糊成一片。
  • transition 列出四个属性各自 0.16 秒：位移、透明度、投影、描边。四种状态（悬停、选中、提示、消除）改的都是这四项，所以一套过渡全接管。
  • .tile img 的 object-fit:cover 是图片不变形的关键：素材不是正方形，cover 按短边铺满再裁掉超出部分，图块始终是方的、照片不会被拉长。pointer-events:none 让图片不吃点击，点击事件落到 .tile 上，e.target.closest('.tile') 才拿得到坐标。
  • .ph 是图片加载失败时的占位（第五篇第 255 行那个 onerror 加的类）：居中显示编号数字，底色用主色掺进卡片底 14%，和正常卡片明显不同又不刺眼。

五个状态类全部由 JS 加、JS 删，样式这边只定义「加上了长什么样」。

  • :hover 上浮 2 像素。触屏没有悬停，这条只在鼠标设备上生效，不影响触屏。
  • .sel 是已选中的那张：描边换主色，外面再套一圈 3 像素的主色光环（box-shadow:0 0 0 3px 这种写法是「不占布局的描边」，用扩散半径当第二层边框），同时保持上浮。第七篇的选中状态机就靠这一个类把「已经点了一张」这件事告诉玩家。
  • .hint 用 animation 而不是 transition：提示要持续呼吸，infinite 加 0.9 秒一轮；第四篇里 1800 毫秒后把类去掉，正好两轮。
  • .bad 是连不上时的左右抖，0.22 秒一次性动画，@keyframes shake 里 25% 和 75% 各偏 4 像素。第四篇提到这个类 240 毫秒后被移除，时长对得上。
  • .gone 是消除：透明度归零同时缩到 0.55 倍。第七篇里加完这个类再等 220 毫秒才把元素从页面删掉，那 220 毫秒就是给这条过渡留的。
  • @keyframes 是动画的关键帧表，pulse 只写了 50% 一个中间状态，起止由元素自身样式推出来；shake 写 25% 和 75% 两个点。

折线、提示条、弹窗

  • 折线元素由第三篇的 drawPath 现场创建，样式只有一条 polyline 规则管它：不填充、描主色、4 像素粗、端点和拐角都修圆（stroke-linecap、stroke-linejoin），95% 不透明度。拐角不修圆会出现尖刺，端点不修圆短线段看着比实际短。
  • .out 是 120 毫秒后加上的淡出类，0.2 秒过渡，配合第三篇里 220 毫秒清空画布。
  • #toast 用「固定定位 + 水平居中 + 默认透明」三件事：left:50% 把左边缘放到屏幕正中，再用 translateX(-50%) 把自己往左挪半个身位，于是真正居中，这个写法不需要知道自身宽度。bottom:26px 浮在底部。
  • 平时 opacity:0 且 pointer-events:none，加上 .on 才显形并同时上移 12 像素（transform 里那两个位移的差值就是浮起的动效）。max-width:88vw 保证长文案在手机上也留得下两侧边距。
  • 颜色是反相的：--ink 当底、--bg2 当字，深色模式下这套反相仍然成立，因为它用的还是令牌。
  • #mask 是全屏遮罩：position:fixed; inset:0 铺满视口，display:flex 加两个 center 让弹窗绝对居中，padding:16px 保证小屏上弹窗不贴边。z-index:20 压在顶栏（5）之上。
  • 遮罩底色是带透明度的深蓝黑，不是纯黑半透明：纯黑在深色模式下会把整个页面糊成一团，看不出是「哪一关打完了」。
  • .dlg 的 width:min(360px,100%) 是「360 像素，但绝不超过可用宽度」，比 max-width 更直白：宽屏固定 360，窄屏自动铺满减边距。
  • .go 是主按钮，反色填充加白字。它的悬停规则单独写一条，否则会被前面 button:hover 那条「描边变主色、文字变主色」的规则破坏成白底白字。

窄屏那三条

整份样式文件只有这一个断点，而且三条全是「收边距和字号」，没有一条改布局。原因在写法上：布局本身是自适应的（auto-fill 网格、flex-wrap 顶栏、min() 弹窗宽、第五篇的格子计算），窄屏不需要另一套结构，只需要把留白和字号压下来，让内容多占一点横向空间。断点取 640 是常见手机竖屏的分界，比它窄就进这一组。

自测

  1. 二十颗关卡按钮为什么由脚本现场造，而不是在 HTML 里写二十个 <button>？
    答：按钮上那行说明文字要同时读关卡表和本地存档，内容是列数、行数、图案种类、限时、最高分、是否解锁。写在 HTML 里就得在两处保持同步，改一关要动两个地方；由脚本造一次就把两份数据拼进同一行文字。代价是首页容器初始是空的，要等脚本执行完才有内容。
  2. [hidden]{display:none !important} 里为什么必须带 !important？
    答：[hidden] 属性选择器权重低，而 #hud、#act 这些带 id 的规则直接写了 display:flex，权重更高，会把隐藏效果盖掉，元素照样显示。整页用 hidden 当唯一的界面切换手段，这条规则是地基，必须顶到最高优先级。
  3. 顶栏和按钮区都写了 flex-wrap:wrap，各自解决什么？
    答：顶栏折行解决窄屏下站名、状态条、图标块挤不下的问题，折行后 #tools 的 margin-left:auto 仍然让它贴右。按钮区折行解决三个按钮在小屏上排成一排超出宽度的问题，折成两行时 keepBottom() 读 offsetHeight 会自动多留高度。
  4. #levels 那一行网格为什么能同时适配宽屏和手机？
    答：repeat(auto-fill,minmax(150px,1fr)) 让列数由容器宽度自己算：每列至少 150 像素，放得下几列放几列，余量按比例摊。宽屏七列、手机两列，不需要为不同宽度各写一套规则。写死列数会在中间尺寸留出一大块空白。
  5. 图块为什么要外层 div 加内层 span 两层，一层不行吗？
    答：一层能显示，但职责会混。外层是 position:absolute 加 JS 写的 left、top、width、height，管「在哪个格子、多大」；内层管外观与动画，并且靠 calc(100% - 6px) 内缩留出相邻缝隙。格子边长由第五篇算出、随时可能变小，内缩写在百分比里就不需要 JS 参与。
  6. .tile img 的 object-fit:cover 和 pointer-events:none 各解决什么问题？
    答：素材不是正方形，直接拉伸会变形，cover 按短边铺满再裁掉超出部分，图块始终方正。pointer-events:none 让图片不吃点击，事件落到 .tile 上，点击处理里 e.target.closest('.tile') 才能稳定拿到格子坐标；否则点在图片上时目标元素不同，选中逻辑会漏。
  7. #toast 的居中为什么要 left:50% 再加 translateX(-50%)？
    答：left:50% 只把元素左边缘放到屏幕正中，元素本身有宽度，会偏右。再往左挪自身的一半才真正居中，而且不需要知道自身多宽。同一句 transform 里多出的 12 像素位移被 .on 去掉，就顺带成了浮起动效。
