06-界面骨架与样式

发表于2026-11-05|更新于2026-11-08|学习小游戏
|浏览量:

骨架：一个文件装三个界面

  • 第 4 行 <!DOCTYPE html>：声明这是标准模式页面。浏览器对同一份 CSS 在标准模式和怪异模式下算法不同，比如盒模型和图片基线对齐，少了这一行，第五篇那些像素计算会整体偏移。
  • 第 5 到 12 行是一个完整页面的头：<html> 带语言、<head> 里依次是字符集、视口、图标、标题、样式表，第 12 行 </head> 之后才是 <body>。这一页自己就是一个完整的 HTML 文档，不依赖任何外部模板。
  • lang="zh-CN" 告诉浏览器和读屏软件正文语言，影响断词、朗读和字体回退。
  • charset="UTF-8" 必须放在 <head> 很靠前的位置：浏览器在读到它之前，字节流是按默认编码解释的，放晚了中文会先乱一下。
  • viewport 三个值：width=device-width 让页面宽度等于设备宽度（不加就按 980 像素排版再缩小，手机上字会糊成一团）、initial-scale=1 是初始缩放比例、viewport-fit=cover 让页面铺到刘海和圆角区域，配合样式里的 env(safe-area-inset-*) 使用。
  • <title> 写的是「小游戏」而不是某一个游戏的名字。页面装着三个游戏，写死谁都不对；进入哪个游戏，脚本会同时改顶栏站名和这里的标题（第七篇的 setBrand）。HTML 里放一个中性的默认值，是为了脚本还没跑时标题不至于空白或说谎。
  • 样式表用相对路径 style.css，脚本同理用 script.js。相对路径让这三份文件可以整体挪到任何目录下都能跑，第五篇和第七篇里那些像素计算也不依赖根路径。图片路径 img/image0.jpg 同样是相对写法。

<body> 里只有六块，按顺序是：

顶栏只留两块：左边的站名，右边贴边的两个图标按钮。关卡、剩余、分数、限时那一排状态数字不在这里，它们在棋盘旁边那一栏（下一节）。原因是顶栏是 position:sticky 粘住的，越窄越稳；状态数字每 100 毫秒写一次，摆在一栏里读比摆在横条里读得顺。

  • 站名那块带 id="brand"：默认文字是「小游戏」，进入某个游戏后由脚本改写成「连连看」「美图消消乐」或「记忆翻牌」，回到首页再改回来。没有这个 id，脚本就找不到要改的那个节点。
  • 两个图标按钮的图标是内联 SVG：viewBox="0 0 24 24" 是这套图标的坐标系，<path d="..."> 是形状描述。内联而不是 <img> 的原因在样式里：fill:currentColor 让图标颜色跟着按钮文字色走，悬停变色时图标一起变。
  • aria-label 给读屏软件一个名字（按钮里只有图形没有文字）；aria-hidden="true" 让 SVG 本身对读屏不可见，避免念出一串路径数据。
  • #bMusic 里那条 <line class="slash"> 是「静音斜杠」，默认 display:none，音乐关掉时加上 off 类才出现（样式第 43 到 44 行）。

<main> 里两个 <section>，一个首页、一个对局，靠 hidden 互斥切换。这是整页唯一的「界面切换」机制：没有路由、没有第二个 HTML 文件，renderHome 和 start 各自改这几个 hidden。

  • #gtabs 是三个页签按钮，一个游戏一颗，on 类标出当前页签。三个游戏共用同一排关卡按钮和同一行汇总，页签只负责「下一排按钮该按哪张关卡表来造」。切换的写入端在第七篇：点页签改存档里的 game 字段再调 renderHome，下面所有空位跟着重填。页签是 HTML 里唯一为「三个游戏」多写出来的结构——其余地方都是改文字、改类名，不再长新节点。
  • .lead 那句玩法说明也带上了 id="lead"，原因和站名一样：三个游戏规则不同，这句话由脚本按当前页签重写。HTML 里放的是连连看的话，只是脚本没跑时的默认值。
  • .tip 是后加的一行小提示，管图片首次加载慢这件事。它不参与任何逻辑，纯文字；样式里只给了字号和颜色，没有 id，脚本永远不碰它。
  • #levels 是个空容器。二十颗关卡按钮由 renderHome 现场造出来（第七篇），因为按钮上的说明行要读关卡表和存档，写在 HTML 里就得手动同步两处——现在有三张关卡表，更不可能预先写死。
  • .sum 那行汇总同样只留 id 空位。
  • 第 52 行 </main> 把这两个 section 合上，下面接的是浮层与脚本。

对局区只有两个直接子元素：#side（状态加按钮）和 #stage（棋盘）。上下还是左右，完全由样式决定，HTML 里没有为窄屏另写一份结构。

  • #side 包的是「非棋盘」的那一组，它自己不带样式（样式里先写成 display:contents，宽屏才变成一栏），存在的理由就是让状态和按钮能被当成一个整体挪到右边，而不用在两个位置之间搬 DOM 节点。
  • #stat 装状态条和进度条，#act 装三个按钮：真正带 hidden 的是 #hud 与 #act，#stat 自己不带。toolset(true) 只显式打开 #act 和 #bHome，#hud 由 renderHome / 三个 start 函数各自设置；第五篇的 keepBottom 读的是 #act 的 hidden 状态和 offsetHeight。
  • #hud 四行，每行是「<i> 说明 + <b> 数字」。数字用 <b> 而不是 <span>，是为了让样式能只挑数字加粗，说明文字保持细体；<i> 只用来当标签，样式里把它的斜体去掉。四个 <b> 都带 id，是第七篇 syncHud 的写入目标。
  • 第二行和第四行的说明文字、第二行末尾的单位也带 id（hL2、hU2、hL4）：三个游戏共用这四行，含义靠换字实现。连连看是「剩余 N 对 / 限时 02:30」；消消乐把第二行换成「步数」并藏起单位，第四行换成「目标」——显示的不是分数而是一个总进度百分比（各条目标进度的平均值）；翻牌是「剩余 N 对」，第四行在亮牌阶段叫「明牌」显示倒数秒数，翻面后按关卡改成「限时」或「配对」：有配对限时的关卡显示 07:00 这样的倒计时，不限时的前四关标签为「配对」、hTime 显示「不限时」。同一个格子装不同游戏最要紧的那个数，四行布局一处不排第二遍。
  • #hud 带着 hidden：初始在首页，状态条不该占位。hidden 是 HTML 布尔属性，写上去就是「藏起来」，样式里第 29 行还专门给它兜底。
  • 棋盘那一行是本页唯一的四层嵌套：#stage 是区块容器，#board 管尺寸与背景，#line 是画折线的 SVG 层，#tiles 是装图块的层。后两层都是 position:absolute; inset:0，叠在同一个盒子里。
  • SVG 写在图块层之前，所以折线画在图块之下。路径只走空格，端点落在图块底下被压住一点，视觉上仍然完整，好处是线永远不会盖住图案。
  • 提示与重排按钮里的 <span class="n"> 是剩余次数，syncTools 写它并据此禁用按钮（第四篇）。
  • 顶栏的状态数字挪进 #stat 之后，font-variant-numeric:tabular-nums（样式第 34 行）的作用没变：每个数字占同样宽度，倒计时跳动时整行不会左右晃。
  • #toast 是底部浮出的短句，空标签，内容每次由 toast() 写进去。
  • #mask 是通关与失败用的遮罩弹窗：外层铺满屏幕并居中，内层 .dlg 是那张卡。标题、正文、两个按钮的文字和点击函数都由 dialog() 六个参数填（第四篇出现过它的调用）。两个按钮都留空，因为按钮文案随场景变：通关时是「下一关」和「首页」，最后一关变成「首页」单按钮，时间到变成「再来一次」和「首页」。
  • <audio preload="none">：不预载音频。浏览器对自动播放有限制，没交互就下载音频是浪费；真正要播时由 ensureMusic 现场设 src 并 play()，失败就提示「点一下屏幕才能出声」（第七篇）。
  • <script> 放在 </body> 之前：脚本里第一件事就是 $('...') 取元素，元素还没解析出来就取到 null。放末尾是最省事的解决办法，不用等任何事件。

样式第一层：令牌与深浅色

:root 选中整个文档根，写在这里的 --名字 是自定义属性，也就是「令牌」：一个值起个名，后面到处用 var(--名字) 取。这十个名字各管一件事：--bg1/--bg2 页面渐变两端、--ink 主文字、--ink2 次要文字、--card 卡片底、--line 描边、--accent/--accent2 主色与主色的深一档、--danger 时间告急、--shadow 卡片投影。

深色模式的全部实现就是这七行：prefers-color-scheme:dark 是系统设置查询，命中时把同名令牌换成一套深色值。整份样式文件里除了这两块之外没有任何一处再判断深浅，因为所有规则都只写 var(--token)。换一套颜色不需要动任何一条布局规则，这是令牌写法唯一但足够的回报。

--ink:rgba(255,255,255,.9) 用半透明白而不是纯白：纯白在深底上对比过强，长时间看字会发虚，降到九成白柔和一些。--shadow 在深色下换成黑色投影，浅色下是带蓝灰的阴影，同一个变量名，两种物理含义。

  • *{box-sizing:border-box}：把所有元素的盒模型改成「宽度含内边距和边框」。默认写法是内容宽度再加内边距，算尺寸时要减来减去；改成 border-box 之后 width:34px 就是最终占位 34 像素。第五篇里 cell 乘出来的尺寸和图块的 width/height 能直接对上，靠的是这一行。
  • html,body{height:100%}：给视口高度一个可参照的锚，#mask 那种 position:fixed; inset:0 不依赖它，但页面在内容很少时也能铺满渐变背景。
  • margin:0：浏览器给 body 默认 8 像素外边距，不清掉会在四周留一圈白，#stage 的可用宽度也会跟着算错。
  • linear-gradient(160deg,...)：160 度方向的线性渐变，两个端点是那两个背景令牌。
  • font 是简写，一次给出字号、行高和字体列表。15px/1.6 是 15 像素字号配 1.6 倍行高。字体列表从系统字体族开始（苹果系、Google 系），中文依次回退到苹方、冬青黑体、微软雅黑，最后 sans-serif 兜底。列表里带空格的名字要加引号。
  • -webkit-text-size-adjust:100%：关掉移动端「根据内容自动放大字号」的行为。这个行为会破坏第五篇算出来的格子与文字比例，页面里已经有 viewport 声明，不需要再放大一次。

顶栏：粘住、模糊、避开刘海

  • display:flex 让三块水平排开，align-items:center 垂直居中，gap:10px 是块间距（比用外边距干净：最后一块后面不会多出空隙）。
  • flex-wrap:wrap：窄屏放不下时允许折行。顶栏里 #tools 用 margin-left:auto 贴右，一旦折行，图标块会另起一行仍然贴右，站名在上面一行，不会出现文字压在图标上的重叠。
  • padding 的左右用 max(16px, env(safe-area-inset-left))：env() 取系统安全区距离，横屏有刘海的设备上是二三十像素。max 的意思是「至少 16 像素，刘海更宽就按刘海来」，两头都不会贴边。
  • position:sticky; top:0：粘顶。页面在棋盘超出时向下滚，顶栏留在原位，倒计时和分数始终可见。z-index:5 保证它盖在滚动内容之上。
  • color-mix(in srgb, var(--bg2) 88%, transparent)：把背景色和透明色按 88% 混，得到一个半透明底。配 backdrop-filter:blur(6px) 就是毛玻璃：底下滚过去的图块被模糊成一片，顶栏文字仍然清晰。两者要一起用，半透明不配模糊会透出杂乱的图块边缘。

[hidden]{display:none !important} 这一行值得单独讲。属性选择器 [hidden] 的权重很低，而后面很多规则直接给元素写了 display：#hud 是 flex、#tools 是 flex、#act 是 flex。这些带 id 的规则权重远高于 [hidden]，一旦元素被藏起来的同时又命中了某条 display:flex，hidden 属性就失效了，元素照样显示。!important 把这条规则的优先级顶到最高，保证「写着 hidden 就一定不显示」。这是这套界面用 hidden 当唯一切换手段时必须补的一块地基。

#hud 的两条派生规则是为「说明 + 数字」这种一行两件事的形状写的。#hud span 把每一行做成弹性盒，align-items:baseline 让「关卡」两个字和后面的数字踩同一条基线，而不是各自在自己的盒子里垂直居中。说明文字和数字的字面高度不同，用 center 会看出上下错位。gap:6px 是说明和数字之间的气泡，HTML 里两个元素之间没有空格，间距只能由样式给。#hud i 只干一件事：把 <i> 默认的斜体关掉。选 <i> 是因为它语义上是「一个提示性标注」，又不带 <b> 那种强调权重，后面 #hud b 挑数字加粗时不会连带把说明也加粗。

font-variant-numeric:tabular-nums 是等宽数字：每个数字占同一格宽，01:29 变成 01:28 时整行宽度不变，倒计时不会左右抖。

按钮：一套基础样式，两种形状

  • font:inherit：按钮默认不吃页面字体，浏览器会给一套自己的字体，inherit 让它跟随 body。
  • min-height:34px：可点区域的高度下限。手指点击的可靠尺寸在 40 上下，34 是「文字按钮」的下限，图标按钮另用 min-width:40px 撑。
  • touch-action:manipulation：告诉浏览器这块区域只做点击和滚动，不用做双击缩放，移动端因此省掉约 300 毫秒的点击判定延迟。图块上也有这一句。
  • #tools button.ico 只给顶栏那两个图标按钮改形状：内边距换成横向、最小宽 40、用 flex 把 SVG 居中。
  • fill:currentColor 让 SVG 的填充色取按钮的文字色，于是悬停那一句改 color 时图标跟着变，不用单独写图标的悬停规则。
  • 静音斜杠两条规则：默认 display:none，#bMusic 带上 off 类时显示。stroke:currentColor 让斜杠颜色同样跟文字色，fill:none 是因为 <line> 是描边图形。
  • button:hover:not(:disabled)：:not(:disabled) 挡掉禁用按钮。第四篇里提示与重排次数用完会置灰，置灰状态下再给悬停色会误导「还能按」。
  • button .n 是按钮里的剩余次数，用次要文字色压暗，让「提示」两个字比数字更抢眼。

首页：一行流式网格

  • main 的 max-width:1240px; margin:0 auto 是全站内容宽度上限与水平居中。第五篇的 stageBox 不再重复这个数，它直接读 #stage 排版后的 clientWidth，上限留在样式里一处，改这一行棋盘就跟着变。
  • padding 的第三项 calc(40px + env(safe-area-inset-bottom))：底部留白再加手机横条（home indicator）的高度，最后一行按钮不会被系统条压住。
  • .tip 紧跟在 .lead 后面，margin:-10px 0 16px 用负的上边距把两行文字拉近——它是对 .lead 的补充说明，不是同级段落，字号也压到 13。纯展示，脚本不碰。
  • #levels 是本页唯一的网格。repeat(auto-fill,minmax(150px,1fr)) 读作「每列至少 150 像素、能放几列放几列、放不下的余量按比例摊给各列」。列数由容器宽度自己算，不写断点：宽屏七列、平板五列、手机两列，同一行代码。写死列数会在中间尺寸出现一边空一大块的情况。三个游戏共用这张网格，切页签只换里面的卡片，不换网格。
  • .lv 是关卡卡片：text-align:left 是因为按钮元素默认文字居中，卡片里两行文字左对齐才读得顺。
  • .lv .d 那行说明文字用 13 像素和次要色，和上面的关卡名拉开层级。内容随页签变：连连看是 4×6 · 6 种图 · 02:30 · 最高 541（行×列，带聚拢规则的关卡还会多一段 · 聚拢·左），消消乐是 7×7 · 5 种图 · 15 · 20 步（后面还会跟特殊机制），翻牌是 4×5 · 20 张 · 10 对 · 亮牌 12s · 配对 420s · 犯错 8次——拼文字的代码在第七篇，样式这里对内容一无所知。
  • .lv:disabled 是未解锁的关卡：半透明、去投影、光标回到默认。第七篇的 renderHome 用 n<=save.max+1 决定 disabled，样式这边只负责让它看起来不能按。
  • .sum 是首页底部那行汇总，数字同样用等宽数字。

页签的样式只有四行：一排 flex、按钮加大内边距、当前页签反色填充。.gt.on 和弹窗里 .go 主按钮是同一套「反色 = 选中/主要」的语言，flex-wrap:wrap 让窄屏放不下三个页签时折行。.gt.on:hover 单独写一条的原因和 .go 一样：基础 button:hover 那条会把文字改成主色，白底白字就看不见了。

两张图里没有任何一条针对手机写的布局规则，差别全部来自那行 auto-fill。

对局区：三层叠起来的棋盘

  • 进度条是「外框加内条」两层：外框 6 像素高、圆角、overflow:hidden 把内条的两端裁成圆头；内条 height:100% 跟随，宽度由 JS 按百分比写。transition:width .2s 让连续写入看起来是滑动。这个槽位同样被三个游戏复用：连连看填剩余时间的比例，消消乐填各条目标进度的平均比例，翻牌在亮牌阶段填亮牌倒数比例、之后按关卡填配对剩余时间比例（前四关不限时则填已配对比例）——条只管「把 0 到 100 画出来」，量什么由各自游戏的同步函数决定。
  • #bar.low 在形势告急时换成 --danger，是 JS 加类、样式给颜色的分工。告急的定义各游戏不同：连连看是剩余 10 秒以内，消消乐是步数只剩 3 步，翻牌在亮牌阶段不看、配对期限时是剩余 30 秒以内、不限时关卡是犯错次数逼近上限。样式不知道也不需要知道这些阈值，只认 low 这个类名。
  • #game 在窄屏是一条纵向的 flex：进度与状态在上、棋盘在中、按钮在下。#side 的 display:contents 是把这一层「拿掉」。它自己不生成盒子，两个孩子 #stat、#act 直接算作 #game 的孩子，于是能参与 #game 的排列。DOM 里 #side 写在 #stage 前面，但 order 是 1 和 3，#stage 是 2，所以视觉上棋盘仍在中间。order 只改视觉顺序，不改代码取元素的顺序，也不改读屏与键盘 Tab 的顺序。
  • #stage 只有 order 和 display 两件事，没有 overflow。它不是滚动容器：棋盘比一屏高时它把页面撑高，滚动用的是浏览器自带的那条纵向滚动条，第五篇末尾讲了为什么这样分工。
  • #act 是三个按钮，justify-content:center 居中、flex-wrap:wrap 让窄屏折行。第五篇的 keepBottom() 读它的 offsetHeight，所以折成两行时预留高度会自动变大，不需要代码知道它现在几行。
  • #board 的 position:relative 是给里面两层绝对定位当参照：inset:0 的含义是「贴着最近那个定位祖先的四条边」，没有这句 relative，图块会相对整个页面定位，坐标全错。margin:0 auto 让棋盘在区块里水平居中。底色用 color-mix 把卡片色和透明混到 55%，得到一块比页面略亮又透出渐变的板面。
  • 那圈 1 像素的描边写成 box-shadow:inset 0 0 0 1px 而不是 border:1px：内阴影不占布局，盒子的宽高就是第五篇 JS 写进去的 (cols+2)*cell，图块的 left、top 不会整体偏移一个描边的厚度；换成 border 就要在算式里补那 2 个像素。
  • #tiles 的三条不可选：user-select:none 禁止连点选中文字（图块里没有文字，但双击会触发选择逻辑），-webkit-touch-callout:none 关掉 iOS 长按弹出的菜单，否则按住图块会弹出「拷贝/查询」浮层，打断连点。
  • #line 的 pointer-events:none 是第三篇画折线那节的另一半：SVG 铺满整个棋盘，不关掉事件就会挡住下面的图块，线一画出来那块区域就点不动。overflow:visible 允许折线画到盒子边缘之外不被裁。

图块：一个元素，五种状态

  • .tile 是第五篇 tileEl 造出来的那个 div，三个游戏的图块都是它，position:absolute 配合内联的 left、top、width、height 落到具体格子上。它自己不带任何可见外观（padding:0; border:0; background:none），外观全在内层 span 上。
  • 分成两层的原因：外层负责「在哪个格子、多大」，由 JS 按数据算；内层负责「长什么样、怎么动」，由样式负责。内缩 6 像素（calc(100% - 6px)）加上 flex 居中，让相邻图块之间留出缝，格子边长再小也不会糊成一片。
  • transition 列出四个属性各自 0.16 秒：位移、透明度、投影、描边。四种状态（悬停、选中、提示、消除）改的都是这四项，所以一套过渡全接管。
  • .tile img 的 object-fit:cover 是图片不变形的关键：素材不是正方形，cover 按短边铺满再裁掉超出部分，图块始终是方的、照片不会被拉长。pointer-events:none 让图片不吃点击，点击事件落到 .tile 上，e.target.closest('.tile') 才拿得到坐标。
  • .ph 是图片加载失败时的占位（第五篇第 339 行那个 onerror 加的类）：居中显示编号数字，底色用主色掺进卡片底 14%，和正常卡片明显不同又不刺眼。

五个状态类全部由 JS 加、JS 删，样式这边只定义「加上了长什么样」。

  • :hover 上浮 2 像素。触屏没有悬停，这条只在鼠标设备上生效，不影响触屏。
  • .sel 是已选中的那张：描边换主色，外面再套一圈 3 像素的主色光环（box-shadow:0 0 0 3px 这种写法是「不占布局的描边」，用扩散半径当第二层边框），同时保持上浮。第七篇的选中状态机就靠这一个类把「已经点了一张」这件事告诉玩家。
  • .hint 是三个游戏共用的「看这里」：描边常亮主色，再加一个 0.6 秒一轮的呼吸动画——光环从贴边的 4 像素鼓到 14 像素，图块同时上浮 8 像素、放大到 1.1 倍再落回去。放大和上浮是后来加的：只靠光环在满屏同图案的棋盘上不够抢眼，整个图块动起来，余光也扫得到。第四篇里 2600 毫秒后把类去掉，够呼吸四轮多。
  • .bad 是连不上时的左右抖，0.22 秒一次性动画，@keyframes shake 里 25% 和 75% 各偏 4 像素。第四篇提到这个类 240 毫秒后被移除，时长对得上。
  • .gone 是消除：透明度归零同时缩到 0.55 倍。第七篇里加完这个类再等 220 毫秒才把元素从页面删掉，那 220 毫秒就是给这条过渡留的。
  • @keyframes 是动画的关键帧表，hintPulse 写了 0%（和 100% 共用）与 50% 两个状态，中间怎么走由浏览器补；shake 写 25% 和 75% 两个点。

翻牌的背面与消消乐的滑动

图块的五个状态是三个游戏共用的，这一段是两个游戏各自的专属规则。

选择器都带 #tiles.m3 或 #tiles.mem 前缀：容器挂上哪个类，哪一组规则才生效。这就是「同一个棋盘、同一批图块元素，按模式换行为」在样式侧的实现——脚本在 startM3、startMem 里给 #tiles 加类，进连连看再摘掉，样式这边不判断任何游戏状态。

  • 消消乐只有一行：给 .tile 的 left、top 加 0.18 秒过渡。第五篇末尾讲过它的图块怎么从棋盘上方滑进空位——纯算术写出的新 top 值，配上这条过渡就自动成了动画。连连看和翻牌的图块从不移动位置，这条规则对它们无意义，所以只挂在 m3 容器下。
  • 翻牌的正面和背面是叠在同一个图块里的两层：img 是正面，.bk 是背面。两张都是 position:absolute; inset:0 铺满内层 span，谁在上由透明度决定。down 类表示「扣着」：正面 opacity:0、背面 opacity:1；摘掉 down 正面回来、背面隐去，各自的 0.16 秒过渡让这一翻是渐变而不是闪变。
  • 背面的花纹是两层渐变叠出来的：repeating-linear-gradient 的斜条纹用主色掺透明，铺出一层织纹；下面再垫一层 160 度的 linear-gradient 从主色渐到另一种主色。两个方向都用 color-mix 掺令牌，深色模式下自动换装，不用另写一套。
  • 为什么不用 3D 翻转（rotateY 加 backface-visibility）：内层 span 有 overflow:hidden，三维变换在里面会被压扁成平面，翻不出效果；而且透明度渐变 0.16 秒干净利落，翻牌游戏的「翻」要的是「换了一面」这个信息，不是转体动作。选透明度还有一个好处：正反两层始终都在，谁显谁隐只是两个数字，不用管理「哪面朝上」的变换状态。
  • down 时 span 缩到 0.96 倍，是一个轻按下去的手感；悬停又弹回 1。正面朝上（没有 down）的图块没有这条，因为它马上要参与配对判断，外形不该再变。
  • .bk 在 tileEl 里的创建是带条件的（第五篇第 334 到 336 行）：只有容器挂着 mem 类才往图块里塞背面元素。消消乐和连连看的每个图块因此少一个节点。

目标面板与障碍层的样式

右侧 #stat 里的 #goals 面板由脚本创建，消消乐与翻牌共用：

  • #goals 是 #stat 里的一段，不另做卡片，用一条上边框和状态条分开；每条目标一行，左边是 22 像素的小图标，中间是名称，右边是 当前/目标。指定元素那行的图标直接铺 img/imageN.jpg，让玩家一眼看到本关要消哪种图；冰块、木箱、掉落物各有自己的小色块或 SVG 图标。翻牌用它显示「配对」限时与「已犯错」两行，以及剩余对子、提示 / 重排次数。
  • 障碍层 #ov 与图块层叠在同一个盒子里，pointer-events:none 保证点击落到下面的图块；.ovcell 用 left / top 定位，尺寸就是 G.cell。
  • 冰块必须半透明：rgba(186,239,255,.38) 到 rgba(78,168,225,.24) 的渐变加白色描边，下面那张图案仍看得清，玩家才能靠图案去凑三连把它打碎；木箱反过来是不透明的木纹色块加深色边框，表示这一格锁住、不能交换。两者都是图标 / 色块而不是新图片，不用往 img/ 里加素材。
  • 掉落物是 #tiles.m3 .tile.drop：金色径向渐变打底，中间一枚星形 SVG；.broken 类让打碎的冰块 / 木箱缩着淡出，用的还是图块那套 0.2 秒过渡。#board.exit #tiles.m3::after 在有掉落物目标的关卡给棋盘底边画一条 4 像素金线，标出「最底行出口」（exit 类由 startM3 按 G.dropNeed 挂上）；.tile.drop.gone span 的 transition-delay:.18s 让掉落物先滑到这一行、再淡出，收集点才看得见。有掉落物目标时 m3RenderGoals 还会在面板标题写出「出口列 X/Y/Z」，玩家看得到该消哪几列。

折线、提示条、弹窗

  • 折线元素由第三篇的 drawPath 现场创建，样式只有一条 polyline 规则管它：不填充、描主色、4 像素粗、端点和拐角都修圆（stroke-linecap、stroke-linejoin），95% 不透明度。拐角不修圆会出现尖刺，端点不修圆短线段看着比实际短。
  • .out 是 120 毫秒后加上的淡出类，0.2 秒过渡，配合第三篇里 220 毫秒清空画布。
  • #toast 用「固定定位 + 水平居中 + 默认透明」三件事：left:50% 把左边缘放到屏幕正中，再用 translateX(-50%) 把自己往左挪半个身位，于是真正居中，这个写法不需要知道自身宽度。bottom:26px 浮在底部。
  • 平时 opacity:0 且 pointer-events:none，加上 .on 才显形并同时上移 12 像素（transform 里那两个位移的差值就是浮起的动效）。max-width:88vw 保证长文案在手机上也留得下两侧边距。
  • 颜色是反相的：--ink 当底、--bg2 当字，深色模式下这套反相仍然成立，因为它用的还是令牌。
  • #mask 是全屏遮罩：position:fixed; inset:0 铺满视口，display:flex 加两个 center 让弹窗绝对居中，padding:16px 保证小屏上弹窗不贴边。z-index:20 压在顶栏（5）之上。
  • 遮罩底色是带透明度的深蓝黑，不是纯黑半透明：纯黑在深色模式下会把整个页面糊成一团，看不出是「哪一关打完了」。
  • .dlg 的 width:min(360px,100%) 是「360 像素，但绝不超过可用宽度」，比 max-width 更直白：宽屏固定 360，窄屏自动铺满减边距。
  • .go 是主按钮，反色填充加白字。它的悬停规则单独写一条，否则会被前面 button:hover 那条「描边变主色、文字变主色」的规则破坏成白底白字。

两条断点

这一组全是「收边距和字号」，没有一条改布局。原因在写法上：布局本身是自适应的（auto-fill 网格、flex-wrap 顶栏、min() 弹窗宽、第五篇的格子计算），窄屏不需要另一套结构，只需要把留白和字号压下来，让内容多占一点横向空间。断点取 640 是常见手机竖屏的分界，比它窄就进这一组。

另一条断点改的是布局，而且只改这一处：880 像素以上，#game 从纵向 flex 换成两列网格，棋盘占左列，#side 那一组占右列。

  • grid-template-columns:minmax(0,1fr) 216px：右列固定 216 像素，左列吃掉剩下的。左列写成 minmax(0,1fr) 而不是 1fr，是因为 1fr 的最小值是内容的自然宽度，棋盘盒子是 JS 写死的像素宽，一旦比算出来的列宽还大就会把列撑开、把右列挤扁；下限写 0 才让「列宽由网格决定，超出的宽度由第五篇的算式负责收进去」这条成立。
  • #stage 和 #side 都显式写了 grid-column 与 grid-row。看着多余：按源码顺序 #side 在 #stage 前面，网格会自动把它们排成第 1 列和第 2 列，但自动排布有一条游标规则：一旦某个元素指定了比游标更靠前的列，游标就会换到下一行，结果是棋盘被推到第二行去。两行都写死，位置就只由这两条声明决定。
  • align-self:start 是给右栏的卡片用的。网格的行高默认由这一行里最高的格子决定，而左列的棋盘很高；不写这一句，#stat 那张卡会被拉伸到和棋盘一样高，卡片底和描边会拉成一整条竖幅。
  • #side 在窄屏是 display:contents，到宽屏换成 display:flex; flex-direction:column，也就是「这一层重新成为盒子」，状态卡和按钮组才有一个共同的容器可以排。#stat 补上卡片外观（底色、描边、圆角、投影），和首页的关卡卡用的是同一组令牌，视觉上是同类东西。
  • #hud 和 #act 都改成纵向。#hud i{margin-right:auto} 把说明文字推向左、数字推到右，四行读起来像一张表；#act button 加 justify-content:space-between 是同一件事的另一半，让「提示」和剩下的次数分居按钮两头。窄屏那头这两条都不生效，仍是横排的小按钮。
  • #barwrap 的外边距从 margin-bottom:14px 换成 margin:12px 0 0：窄屏时进度条在棋盘上方，间距要留在下边；宽屏时它跑到卡片里、状态数字下面，间距该留在上边。

这两条断点加起来只动 #game 内部的排布，页面其余部分（顶栏、首页网格、弹窗）不受影响。第五篇的 SIDE=matchMedia('(min-width:880px)') 就是这一行的镜像：JS 需要知道按钮是否还占底部高度，只能问同一个宽度阈值。

自测

  1. 几十颗关卡按钮为什么由脚本现场造，而不是在 HTML 里写死？
    答：按钮上那行说明文字要同时读关卡表和本地存档，内容是棋盘、图种、目标或限时、最高分、是否解锁，而且三个页签的关卡数还不一样（20 / 30 / 20）。写在 HTML 里就得在两处保持同步，改一关要动两个地方；由脚本造一次就把两份数据拼进同一行文字。代价是首页容器初始是空的，要等脚本执行完才有内容。
  2. [hidden]{display:none !important} 里为什么必须带 !important？
    答：[hidden] 属性选择器权重低，而 #hud、#act 这些带 id 的规则直接写了 display:flex，权重更高，会把隐藏效果盖掉，元素照样显示。整页用 hidden 当唯一的界面切换手段，这条规则是地基，必须顶到最高优先级。
  3. 顶栏和按钮区都写了 flex-wrap:wrap，各自解决什么？
    答：顶栏折行解决窄屏下站名和两个图标块挤不下的问题，折行后 #tools 的 margin-left:auto 仍然让它贴右。按钮区折行解决三个按钮在小屏上排成一排超出宽度的问题，折成两行时 keepBottom() 读 offsetHeight 会自动多留高度。
  4. #levels 那一行网格为什么能同时适配宽屏和手机？
    答：repeat(auto-fill,minmax(150px,1fr)) 让列数由容器宽度自己算：每列至少 150 像素，放得下几列放几列，余量按比例摊。宽屏七列、手机两列，不需要为不同宽度各写一套规则。写死列数会在中间尺寸留出一大块空白。
  5. 图块为什么要外层 div 加内层 span 两层，一层不行吗？
    答：一层能显示，但职责会混。外层是 position:absolute 加 JS 写的 left、top、width、height，管「在哪个格子、多大」；内层管外观与动画，并且靠 calc(100% - 6px) 内缩留出相邻缝隙。格子边长由第五篇算出、随时可能变小，内缩写在百分比里就不需要 JS 参与。
  6. .tile img 的 object-fit:cover 和 pointer-events:none 各解决什么问题？
    答：素材不是正方形，直接拉伸会变形，cover 按短边铺满再裁掉超出部分，图块始终方正。pointer-events:none 让图片不吃点击，事件落到 .tile 上，点击处理里 e.target.closest('.tile') 才能稳定拿到格子坐标；否则点在图片上时目标元素不同，选中逻辑会漏。
  7. #toast 的居中为什么要 left:50% 再加 translateX(-50%)？
    答：left:50% 只把元素左边缘放到屏幕正中，元素本身有宽度，会偏右。再往左挪自身的一半才真正居中，而且不需要知道自身多宽。同一句 transform 里多出的 12 像素位移被 .on 去掉，就顺带成了浮起动效。
  8. 宽屏的右侧一栏为什么用「同一份 HTML 加一条断点」，而不是另写一份结构？
    答：状态和按钮要去的只是另一个位置，不是另一套东西。#side 在窄屏用 display:contents 把自己隐掉、两个孩子靠 order 排在棋盘上下，在宽屏重新生成盒子并排进网格第 2 列，脚本按 id 取元素的代码一行不用改。写两份结构的话，hidden 切换、syncHud 的写入目标、keepBottom 读的高度都会变成两处，界面上多一套 DOM 反而会带来两套状态。
  9. 翻牌的背面为什么用「两层叠加、透明度切换」，而不是 3D 翻转？
    答：内层 span 带 overflow:hidden，三维变换会被压扁成平面，翻不出来；透明度渐变 0.16 秒同样传达了「换了一面」，还省掉管理「哪面朝上」的变换状态。正反两层始终都在，down 类一加一摘就是全部逻辑，深浅色也只走令牌一套。
  10. #hud 的四行为什么要给说明文字和单位也挂 id？
    答：三个游戏共用同一组状态行，要变的只是文字含义：消消乐第二行是「步数」且没有「对」这个单位，第四行是「目标」显示各条目标的平均进度百分比；翻牌开局有「明牌」阶段借第四行显示亮牌倒数，翻面后同一格改显示配对限时或「不限时」。挂上 id 之后换游戏只是几次 textContent 赋值加一次 hidden，四行布局、样式、读屏顺序都不用动第二遍。
