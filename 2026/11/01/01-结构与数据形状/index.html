一个页面装三个小游戏

这一个小游戏页面（/link/）里装了三种玩法，共用同一套界面和同一批图片素材：

游戏 玩法一句话
连连看 点两张相同的图，用一条拐弯不超过两次的折线连起来就消掉
美图消消乐 点相邻两张交换位置，凑齐横或竖 3 张以上相同的图就消除得分
记忆翻牌 牌全背面朝上，每次翻两张，同图配对消掉，不同翻回去

整页由三个文件组成，浏览器直接执行。

文件 管什么
Link/index.html 页面骨架：有哪些块、块之间的层级
Link/style.css 外观：颜色、圆角、动画、深浅色
Link/script.js 逻辑与算法：发牌、判定、计分、存档、三种游戏的切换

这一篇定最底层的东西：三个游戏怎么在同一个页面里切换、各自的棋盘在代码里是什么形状、三张关卡表里的数字各控制什么。后面的每篇都同时讲三个游戏在这一件事上各自的写法。

首页与一盘棋

首页顶部是三个页签按钮，点谁就显示谁的关卡列表。每个按钮上写着这一关的参数：连连看是牌数、图案种类、限时；美图消消乐是棋盘大小、目标分数、步数；记忆翻牌是棋盘大小、对数、步数。有过成绩还会带上最高分。

点进任何一关，页面上都是同样三样东西：状态（关卡、剩余、分数、第四格）、棋盘、三个按钮。左上角的品牌字和浏览器标签页的标题会跟着换：进连连看显示「连连看」，进美图消消乐显示「美图消消乐」，回到首页显示「小游戏」。手机上是棋盘在上、状态贴着棋盘顶、按钮压在棋盘下面；电脑屏幕宽到一定程度，状态和按钮并成右边一栏，棋盘独占左边一大块。同一份 HTML，位置由样式分配，细节在第六篇。

连连看的棋盘：一张比棋盘大一圈的表

页面上看到的是一张 列数 × 行数 的格子图，代码里存的不是这张图，而是一张横竖各多两行两列的表。多出来的那一圈永远留空，专门给连线绕路用。

以 4 列 3 行 为例，# 是有图的格子，. 是那圈空格：

代码里这张表的行号是 0..4、列号是 0..5，真正的图只放在行 1..3、列 1..4 里面。

这圈空格不是摆设。连连看的连线允许从棋盘外面绕过去，最常见的例子是第一行左右两端各有一张相同的图：中间所有直线和折线都堵住了也没用，连线可以往上抬到棋盘外那一行，横着走一段再下来，两个拐弯，照样算连上。

少了这圈空格，边界上的图就少了一整条绕行路线，很多实际能连的组合会被判成连不上。

逐行看：

  • var C=cols+2, R=rows+2;：var 是声明一个变量，一行里用逗号可以连着声明多个。C 是这张表的列数，R 是行数，各比棋盘多 2，就是左右各一圈、上下各一圈。用大写是因为下面几行里 c、r 已经被拿去当小写循环变量了，同一个名字不能两用。
  • var g=[];：g 是这张表本身，[] 是一个空数组。数组就是一排格子，按顺序编号，编号从 0 开始。
  • 第三行是两层循环，外层 r 从 0 走到 R-1，每一轮里层 c 从 0 走到 C-1，row.push(0) 往一行的末尾塞一个 0，g.push(row) 把这一行接到表的末尾。循环跑完，g 是一个 R 项的数组，每一项又是一个 C 项的数组，这就是二维数组：数组的元素还是数组。取值写 g[r][c]，读第 r 行的第 c 个。
  • 这里的 0 是「空格子」的意思，见下一节。
  • 最后两行填图。deck 是一副洗好的牌（第二篇讲怎么洗），k 是发到哪张的计数。r1 从 1 到 rows、c1 从 1 到 cols，正好是那圈空格围起来的内部区域。g[r1][c1]=deck[k++] 里的 k++ 是「先用当前值、再自增」，等价于取 deck[k] 然后 k=k+1，于是一行一行地把牌填满内部区域。

外圈那一圈格子从来不会被写入任何图，也从来不用清空，这就是「绕外圈」能成立的物理原因。

另两个游戏的棋盘：不要外圈的普通表

美图消消乐和记忆翻牌的棋盘就是一张 行数 × 列数 的普通二维数组，没有外圈，行号列号从 0 开始。

这不是偷懒，是玩法不需要。外圈是为「连线绕到棋盘外面」服务的，只有连连看有这种规则。美图消消乐的消除只看横竖方向上紧挨着的几张图，紧挨着这件事只发生在棋盘内部；记忆翻牌更简单，翻牌配对只比较两张图编号是否相同，跟位置毫无关系。给它们也加一圈，等于修一条谁都不走的路，白占屏幕还得多留神别把边界条件写错。

美图消消乐的棋盘在开局时整张随机填图：

1+Math.floor(rnd()*lv.f) 是「从 1 到 lv.f 随机取一个整数」：rnd() 给 0 到 1 之间的小数，乘以 lv.f 再去掉小数部分得到 0 到 lv.f-1，加 1 就对上了「0 表示空格、图案从 1 开始」的约定。填完先过一遍 m3Clean 把开局就存在的三连抹掉（消除游戏的开局不该有现成的消），再检查有没有可交换的一步，没有就整体重填，最多试 60 次。这些函数的内部机制在第三、四篇讲。

表里存的值：0 是空，正整数是图案编号

三个游戏的 g[r][c] 都遵守同一套约定：

值 含义
0 空格。连连看的外圈与已消格、消消乐已消格都是 0
1 到 30 这张格子的图是哪一种。连连看与记忆翻牌里同编号成对出现

判定「两张是不是同一张图」，三个游戏都是第一步比编号：连连看比两张的编号是否相等（第三篇），记忆翻牌在 memTap 里比 M.g[a.r][a.c]===M.g[r][c]（script.js:831），美图消消乐找同号连排。都不用去比像素、也不用管图片文件叫什么名字。

编号与图片文件的对应关系写在生成图块元素的那行：编号 f 对应 img/image + (f-1) + .jpg，也就是编号 1 用 image0.jpg，编号 30 用 image29.jpg。之所以不是编号直接当文件名，是因为图片是从 0 开始编号的一批素材，而代码里 0 已经用来表示空格，编号必须从 1 起，两套编号差了一个 1。

素材总数记在一个常量里，与方向表放在一起：

DIRS 下一节单说。NFACE 是「素材一共准备了 30 种」这条事实的记号，写在代码里备查，发牌并不读它：每关用前几种由关卡表里的 f 决定，编号越界的图不会发出来。img/ 目录里如果缺某一张，图块会在生成时退化成占位的数字，见第五篇。

四个方向 DIRS

每一项是一对数字 [行变化, 列变化]，把当前位置加上一对就得到相邻格子：

项 含义
[-1,0] 行减 1，往上一格
[1,0] 行加 1，往下一格
[0,-1] 列减 1，往左一格
[0,1] 列加 1，往右一格

只有四个，线段只有横着走和竖着走两种形态。判定连线时反复用到这四个，用法是 cur.r+DIRS[d][0] 与 cur.c+DIRS[d][1]，见第三篇。

另两个游戏没有这张方向表。美图消消乐找「横着或竖着连排」用的是直接沿行、沿列扫描（第三篇的 m3FindGroups），不需要「从某格向四个方向试探」这个动作；记忆翻牌压根不看位置。方向表是连线玩法的专用工具，玩法不同，数据结构跟着不同——这也是三个游戏各自一套函数的原因之一。

关卡表 LEVELS

二十行，一行一关：

{c:6,r:4,...} 是一个对象。对象是一堆有名字的值，靠 名字: 值 成对写，用点号取值：level.c 拿到 6，level.t 拿到 150。数组里放对象，就是「一关一条记录」。

键 含义 用在哪
c 棋盘列数 发牌、首页那行说明文字
r 棋盘行数 同上
f 这一关用前几种图案 发牌时决定图案编号的循环上限
t 限时，单位秒 倒计时起始值、首页文字、剩余时间的奖励
h 提示次数 提示按钮的次数与禁用条件
s 重排次数 重排按钮的次数与禁用条件

几个从这张表里能读出来的取舍：

  • c 与 r 的乘积一定是偶数。牌要成对发，总数必须是偶数，所以这张表里每一关的行列数都凑成了偶数张。乘积一旦是奇数，最后一张会落单，永远消不掉。
  • c 与 r 是设计目标，不是最终行列数。发牌时会在「乘积等于这个牌数」的所有因数分解里，挑一个在当前窗口下放得最大、又最接近设计列数的组合，挑法见第五篇。牌数始终不变，变的只是横竖怎么分配。
  • 行列上限压在 16 列 8 行。手机竖屏太窄，列数一大每格就被挤得过小。限时前十二关跟着牌数涨（第一关 150 秒），棋盘封顶 16×8 之后不再变大，改为逐关收紧时间（最后一关 430 秒）——平均每对牌可用的时间一关比一关少，难度就是这样上去的。
  • 从第一关到最后一关，牌数（c*r）和图案种类（f）一起涨。图多、花样也多，难度自然上去了，但真正卡人的是后两项：h 从 5 降到 1、s 从 3 降到 0。最后三关 s:0 意味着没有重排次数，排成死局只能重玩。
  • 关卡表里没有图的名字，只有编号。换一批素材只要把 img/ 目录里的图片换成同样编号的文件，这张表不用动。

首页那一排关卡按钮上的文字就是按这张表拼出来的：

'文字' + 变量 是字符串拼接，把数字和文字接成一整句。lv.c+'×'+lv.r 得出 6×4 这种形状，fmt(lv.t) 把 150 秒换算成 02:30 的写法（换算函数在第七篇）。(best?' · 最高 '+best:'') 是三元表达式，形如 条件 ? A : B，条件成立取 A 否则取 B，这里的意思是「这一关有过最高分才追加那半句」。

另两张关卡表：M3_LEVELS 与 MEM_LEVELS

美图消消乐和记忆翻牌各有自己的一张二十行关卡表，结构跟 LEVELS 一样是「数组里放对象」，但键的含义有两处关键的错位，读代码时最容易在这里栽跟头。

键 含义 与 LEVELS 的差别
c / r 棋盘列数 / 行数，实际就用这两个数 相同
f 这一关用前几种图案（5 到 10 种） 上限小得多，详见下文
t 目标分数，达到即过关 完全不同：LEVELS 的 t 是限时秒数
m 步数，每交换出一次有效消除减 1 LEVELS 没有这个键
h / s 提示 / 重排次数 相同

f 压到 5 到 10 是消除类玩法的固有约束：图案种类越少，随机填出来的三连和连锁越多，分数涨得越快；种类太多则每步都凑不齐三连，玩起来既慢又挫败。连连看只要求「同图有两张」，30 种照样能玩；消消乐要求「同图至少 3 张连成排」，花样一多就凑不出来了。玩法决定参数范围，这在两张表之间看得最清楚。

m（步数）取代了时间作为第二根约束。倒计时适合「快找快消」的连连看，而消消乐每一步要先观察再交换，用秒表压着会逼人乱点，所以改成给足步数（28 到 52 步）。

记忆翻牌的表是第三张：

键 含义
c / r 棋盘列数 / 行数，乘积是牌总数，除以 2 是对数
f 这一关用前几种图案，共 c*r/2 对
m 翻牌步数：每翻开第二张算一步，用完即失败
h / s 提示 / 重排次数

这张表没有 t：记忆翻牌没有目标分也没有倒计时，过关条件就是配齐全部对子，约束只剩步数。f 与棋盘大小的关系是这张表的内在逻辑——c*r 张牌配成 c*r/2 对，f 越接近对数，图样越不重复，记忆负担越重；f 小则同图多对，翻出一张就能顺带想起它的同伴在哪。

三张表放在一起看，同一个字母在不同表里可以是完全不同的东西（t 在连连看是秒数、在消消乐是分数），读代码时永远要以「这个表自己那一栏的解释」为准，不能想当然。

一局游戏的当前状态：S、G、M

代码里没有第二份棋盘。每个游戏的所有可变成量集中放在一个状态对象里，开局那一刻整个换成新的。连连看的叫 S：

属性 含义
lv 本关的参数表，就是 LEVELS 里那一行
no 第几关，从 1 开始
g 那张大一圈的棋盘表本身
rows / cols 棋盘的行数与列数，不含外圈
cell 一格多少像素，第五篇算的就是这个数
total 开局共有多少张图
left 还剩多少张没消
time 剩余秒数，每 0.1 秒减一次
hint / shuf 剩余的提示与重排次数
score 本关分数
sel 当前选中哪张，没选中是 null
locked 是否正在播放消除动画，用来挡住新的点击

null 是「这里没有东西」，不是 0、也不是空字符串。locked:false 里的 false/true 是布尔值，只有这两个状态，专门用来当开关。

var S=null, timer=0... 那一行里：timer 是定时器的编号（第七篇用它停计时），lastMatch 与 combo 管连续消除的加分。S=null 的含义是「开局前根本不存在任何一局」，所以点击处理进来第一件事都是检查 S 在不在，见第七篇的 tap。

同一段里还剩一个 runBase=S.score，赋值之后没有任何地方读这个变量，属于遗留写法。留着不影响运行，但别按「本关起始分」去理解计分。

美图消消乐与记忆翻牌的状态对象与 S 同构，差别集中在约束那一栏：

属性 连连看 S 消消乐 G（script.js:537-538） 翻牌 M（script.js:760-761）
约束值 time 剩余秒数 moves 剩余步数 moves 剩余步数
过关条件 left 减到 0 score 达到 lv.t left 减到 0（这里的 left 是剩余对数）
进度条画什么 剩余时间的百分比 分数占目标分的百分比 已配对数占总对数的百分比
特有属性 total over（分出胜负后不再响应点击） streak 连对计数、first 第一张翻开的牌、busy 动画锁

三个对象都有 locked 或等价的 busy：动画播放期间挡住新的点击，防止状态被中途改乱。M 的 first 记录第一张翻开的牌，streak 记录连续配对成功的次数（连击加分用），这两个键只有翻牌玩法用得上。

本篇新名词

名词 一句话解释
数组 一排按顺序编号的值，编号从 0 起，写 a[2] 取第三个
二维数组 数组的元素还是数组，写 g[行][列]
对象 一堆有名字的值，写 {名字: 值}，用点号取

分支 if(条件){...} else {...}，按条件走哪条路
函数 一段起名字、可以带参数、可以返回值的代码
参数 调用函数时递进去的值
返回值 函数算完递出来的那个值
三元表达式 条件 ? A : B，二选一
布尔值 只有 true 与 false 两种状态的值
全等 ===，两边值和类型都一样才算相等

自测

  1. 连连看的代码表为什么比棋盘横竖各多两行两列？少这一圈会怎样？ 答：这一圈是留给连线绕棋盘外用的通道。少了这一圈，边界上的图就没有绕行路线，很多本该连得上的组合会被判成连不上。
  2. 美图消消乐和记忆翻牌的棋盘为什么不需要外圈？ 答：外圈是为「连线绕到棋盘外」服务的。消消乐只看相邻格子连成排，翻牌只比两张图编号，都不需要从棋盘外绕路。
  3. g[0][3] 上的值在连连看里有可能不是 0 吗？ 答：不可能。第 0 行是外圈，填牌从行 1 开始，外圈永远是空格。
  4. 表里存的值是 7，代表什么？ 答：这张格子的图是第 7 种图案，对应 img/image6.jpg。三个游戏都遵守这个约定；区别在连连看和翻牌里同编号恰好两张，消消乐里同编号随机分布、可能多于两张。
  5. 连连看关卡表里的 s:0 是什么意思？ 答：这一关的重排次数是 0，重排按钮一开始就是禁用状态，排成死局只能重玩。
  6. 关卡表里写着 c:16，手机窄屏上也一定是 16 列吗？ 答：不一定。c 是设计目标，实际行列由牌数的因数分解在当前窗口里重新挑，挑法见第五篇。
  7. 美图消消乐关卡表里的 t 是时间吗？ 答：不是。它是目标分数，达到就过关；三个游戏里只有连连看的 t 是限时秒数。
  8. MODE、S、G、M 为什么各设一个，而不是合成一个大对象？ 答：分开后每个游戏只操作自己的状态，点击分发只需要一次 MODE 判断；合在一起则每个函数都要面对另外两个游戏的字段，改一处容易碰坏别处。
