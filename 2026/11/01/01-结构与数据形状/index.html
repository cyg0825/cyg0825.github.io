首页与一盘棋

首页是一排关卡按钮，每个按钮上写着这一关的牌数、图案种类、限时，有过成绩还会带上最高分。

点进去之后页面只剩三块：顶部一行状态（关卡、剩余张数、倒计时、分数），中间棋盘，棋盘下面三个按钮。

棋盘在代码里是一张比棋盘大一圈的表

页面上看到的是一张 列数 × 行数 的格子图，代码里存的不是这张图，而是一张横竖各多两行两列的表。多出来的那一圈永远留空，专门给连线绕路用。

以 4 列 3 行 为例，# 是有图的格子，. 是那圈空格：

代码里这张表的行号是 0..4、列号是 0..5，真正的图只放在行 1..3、列 1..4 里面。

这圈空格不是摆设。连连看的连线允许从棋盘外面绕过去，最常见的例子是第一行左右两端各有一张相同的图：中间所有直线和折线都堵住了也没用，连线可以往上抬到棋盘外那一行，横着走一段再下来，两个拐弯，照样算连上。

少了这圈空格，边界上的图就少了一整条绕行路线，很多实际能连的组合会被判成连不上。

建这张表的代码在发牌函数里：

逐行看：

  • var C=cols+2, R=rows+2;：var 是声明一个变量，一行里用逗号可以连着声明多个。C 是这张表的列数，R 是行数，各比棋盘多 2，就是左右各一圈、上下各一圈。用大写是因为下面几行里 c、r 已经被拿去当小写循环变量了，同一个名字不能两用。
  • var g=[];：g 是这张表本身，[] 是一个空数组。数组就是一排格子，按顺序编号，编号从 0 开始。
  • 第三行是两层循环，外层 r 从 0 走到 R-1，每一轮里层 c 从 0 走到 C-1，row.push(0) 往一行的末尾塞一个 0，g.push(row) 把这一行接到表的末尾。循环跑完，g 是一个 R 项的数组，每一项又是一个 C 项的数组，这就是二维数组：数组的元素还是数组。取值写 g[r][c]，读第 r 行的第 c 个。
  • 这里的 0 是「空格子」的意思，见下一节。
  • 最后两行填图。deck 是一副洗好的牌（第二篇讲怎么洗），k 是发到哪张的计数。r1 从 1 到 rows、c1 从 1 到 cols，正好是那圈空格围起来的内部区域。g[r1][c1]=deck[k++] 里的 k++ 是「先用当前值、再自增」，等价于取 deck[k] 然后 k=k+1，于是一行一行地把牌填满内部区域。

外圈那一圈格子从来不会被写入任何图，也从来不用清空，这就是「绕外圈」能成立的物理原因。

表里存的值：0 是空，1 到 30 是图案编号

g[r][c] 只有两种含义：

值 含义
0 空格。包括外圈那圈，以及已被消掉的格子
1 到 30 这张格子的图是哪一种。同一个编号在整个棋盘里成对出现

判定两张图能不能连，第一步就是比编号相同（第三篇），编号不同直接算连不上，不用去比像素、也不用管图片文件叫什么名字。

编号与图片文件的对应关系写在生成图块元素的那行：编号 f 对应 img/image + (f-1) + .jpg，也就是编号 1 用 image0.jpg，编号 30 用 image29.jpg。之所以不是编号直接当文件名，是因为图片是从 0 开始编号的一批素材，而代码里 0 已经用来表示空格，编号必须从 1 起，两套编号差了一个 1。

素材总数记在一个常量里，与方向表放在一起：

DIRS 下一节单说。NFACE 是「素材一共准备了 30 种」这条事实的记号，写在代码里备查，发牌并不读它：每关用前几种由关卡表里的 f 决定（第 16 关起 f:30 才用满），编号越界的图不会发出来。img/ 目录里如果缺某一张，图块会在生成时退化成占位的数字，见第五篇。

四个方向 DIRS

每一项是一对数字 [行变化, 列变化]，把当前位置加上一对就得到相邻格子：

项 含义
[-1,0] 行减 1，往上一格
[1,0] 行加 1，往下一格
[0,-1] 列减 1，往左一格
[0,1] 列加 1，往右一格

只有四个，线段只有横着走和竖着走两种形态。判定连线时反复用到这四个，用法是 cur.r+DIRS[d][0] 与 cur.c+DIRS[d][1]，见第三篇。

关卡表 LEVELS

二十行，一行一关：

{c:6,r:4,...} 是一个对象。对象是一堆有名字的值，靠 名字: 值 成对写，用点号取值：level.c 拿到 6，level.t 拿到 90。数组里放对象，就是「一关一条记录」。

键 含义 用在哪
c 棋盘列数 发牌、首页那行说明文字
r 棋盘行数 同上
f 这一关用前几种图案 发牌时决定图案编号的循环上限
t 限时，单位秒 倒计时起始值、首页文字、剩余时间的奖励
h 提示次数 提示按钮的次数与禁用条件
s 重排次数 重排按钮的次数与禁用条件

几个从这张表里能读出来的取舍：

  • c 与 r 的乘积一定是偶数。牌要成对发，总数必须是偶数，所以这张表里每一关的列数都取了偶数。乘积一旦是奇数，最后一张会落单，永远消不掉。
  • c 与 r 是设计目标，不是最终行列数。发牌时会在「乘积等于这个牌数」的所有因数分解里，挑一个在当前窗口下放得最大、又最接近设计列数的组合，所以第 19 关那个 c:22 在手机上是按别的行列铺开的，挑法见第五篇。牌数始终不变，变的只是横竖怎么分配。
  • 从第一关到最后一关，牌数（c*r）和图案种类（f）一起涨。图多、花样也多，难度自然上去了，但真正卡人的是后两项：h 从 5 降到 1、s 从 3 降到 0。最后三关 s:0 意味着没有重排次数，排成死局只能重玩。
  • 关卡表里没有图的名字，只有编号。换一批素材只要把 img/ 目录里的图片换成同样编号的文件，这张表不用动。

首页那一排关卡按钮上的文字就是按这张表拼出来的：

'文字' + 变量 是字符串拼接，把数字和文字接成一整句。lv.c+'×'+lv.r 得出 6×4 这种形状，fmt(lv.t) 把 90 秒换算成 01:30 的写法（换算函数在第七篇）。(best?' · 最高 '+best:'') 是三元表达式，形如 条件 ? A : B，条件成立取 A 否则取 B，这里的意思是「这一关有过最高分才追加那半句」。

一局游戏的当前状态：S

代码里没有第二份棋盘。整局游戏的所有可变成量集中放在一个对象 S 里，开局那一刻整个换成新的：

属性 含义
lv 本关的参数表，就是 LEVELS 里那一行
no 第几关，从 1 开始
g 那张大一圈的棋盘表本身
rows / cols 棋盘的行数与列数，不含外圈
cell 一格多少像素，第五篇算的就是这个数
total 开局共有多少张图
left 还剩多少张没消
time 剩余秒数，每 0.1 秒减一次
hint / shuf 剩余的提示与重排次数
score 本关分数
sel 当前选中哪张，没选中是 null
locked 是否正在播放消除动画，用来挡住新的点击

null 是「这里没有东西」，不是 0、也不是空字符串。locked:false 里的 false/true 是布尔值，只有这两个状态，专门用来当开关。

第一行里那几个变量：timer 是定时器的编号（第七篇用它停计时），lastMatch 与 combo 管连续消除的加分。S=null 的含义是「开局前根本不存在任何一局」，所以点击处理进来第一件事都是检查 S 在不在，见第七篇的 tap。

同一段里还剩一个 runBase=S.score，赋值之后没有任何地方读这个变量，属于遗留写法。留着不影响运行，但别按「本关起始分」去理解计分。

本篇新名词

名词 一句话解释
数组 一排按顺序编号的值，编号从 0 起，写 a[2] 取第三个
二维数组 数组的元素还是数组，写 g[行][列]
对象 一堆有名字的值，写 {名字: 值}，用点号取
索引 数组里的位置编号
循环 for(起点; 条件; 每轮怎么变)，条件成立就一直执行
函数 一段起名字、可以带参数、可以返回值的代码
参数 调用函数时递进去的值
返回值 函数算完递出来的那个值
三元表达式 条件 ? A : B，二选一
布尔值 只有 true 与 false 两种状态的值
null 表示「没有值」的那个特殊值
字符串拼接 用 + 把文字与数字接成一整段文字
相对路径 / 绝对路径 不带 / 开头的按当前目录找，带 / 开头的从根路径找

自测

  1. 代码里那张表为什么比棋盘横竖各多两行两列？少这一圈会怎样？ 答：这一圈是留给连线绕棋盘外用的通道。少了这一圈，边界上的图就没有绕行路线，很多本该连得上的组合会被判成连不上。
  2. g[0][3] 上的值有可能不是 0 吗？ 答：不可能。第 0 行是外圈，填牌从行 1 开始，外圈永远是空格。
  3. 表里存的值是 7，代表什么？ 答：这张格子的图是第 7 种图案，对应 img/image6.jpg。编号相同的图在棋盘上成对出现。
  4. 关卡表里的 s:0 是什么意思？ 答：这一关的重排次数是 0，重排按钮一开始就是禁用状态，排成死局只能重玩。
  5. c 与 r 的乘积如果是奇数会发生什么？ 答：牌数无法成对，最后一张落单，永远消不掉，那一关不可能过。
  6. 第 19 关写着 c:22，手机上也是 22 列吗？ 答：不是。c 是设计目标，实际行列由牌数的因数分解在当前窗口里重新挑，第 19 关窄屏下是 16 行 11 列，见第五篇。
