01-结构与数据形状

|浏览量:

一个页面装三个小游戏

这一个小游戏页面（/link/）里装了三种玩法，共用同一套界面和同一批图片素材：

游戏 玩法一句话
连连看 点两张相同的图，用一条拐弯不超过两次的折线连起来就消掉
美图消消乐 点相邻两张交换位置，凑齐横或竖 3 张以上相同的图就消除得分
记忆翻牌 牌全背面朝上，每次翻两张，同图配对消掉，不同翻回去

整页由三个文件组成，浏览器直接执行。

文件 管什么
Link/index.html 页面骨架：有哪些块、块之间的层级
Link/style.css 外观：颜色、圆角、动画、深浅色
Link/script.js 逻辑与算法：发牌、判定、计分、存档、三种游戏的切换

这一篇定最底层的东西：三个游戏怎么在同一个页面里切换、各自的棋盘在代码里是什么形状、三张关卡表里的数字各控制什么。后面的每篇都同时讲三个游戏在这一件事上各自的写法。

首页与一盘棋

首页顶部是三个页签按钮，点谁就显示谁的关卡列表。每个按钮上写着这一关的参数：连连看是行×列、图案种类、限时（带聚拢规则的关还会标出方向）；美图消消乐是棋盘大小、同屏元素数、目标类型与目标量、步数以及特殊机制；记忆翻牌是棋盘大小、总牌数、对数、亮牌秒数、配对限时与允许犯错次数。有过成绩还会带上最高分。三张表分别是 20 关（连连看）、30 关（消消乐）、20 关（翻牌），sMaxAll 与 hLvMax 按当前页签显示对应总数。

点进任何一关，页面上都是同样三样东西：状态（关卡、剩余、分数、第四格）、棋盘、三个按钮。左上角的品牌字和浏览器标签页的标题会跟着换：进连连看显示「连连看」，进美图消消乐显示「美图消消乐」，回到首页显示「小游戏」。手机上是棋盘在上、状态贴着棋盘顶、按钮压在棋盘下面；电脑屏幕宽到一定程度，状态和按钮并成右边一栏，棋盘独占左边一大块。同一份 HTML，位置由样式分配，细节在第六篇。

三个游戏怎么在一份代码里切换

切换的答案是一个全局变量 MODE，取值 'link'、'm3'、'mem' 三选一。每个游戏有自己的开局函数，谁被调用谁就先把 MODE 改成自己，再把状态对象换成自己的。

=== 是「全等」：两边不但值一样，类型也得一样，'1'===1 是 false。写判断时用它不容易踩到类型转换的坑。

连连看的棋盘：一张比棋盘大一圈的表

页面上看到的是一张 列数 × 行数 的格子图，代码里存的不是这张图，而是一张横竖各多两行两列的表。多出来的那一圈永远留空，专门给连线绕路用。

以 4 列 3 行 为例，# 是有图的格子，. 是那圈空格：

代码里这张表的行号是 0..4、列号是 0..5，真正的图只放在行 1..3、列 1..4 里面。

这圈空格不是摆设。连连看的连线允许从棋盘外面绕过去，最常见的例子是第一行左右两端各有一张相同的图：中间所有直线和折线都堵住了也没用，连线可以往上抬到棋盘外那一行，横着走一段再下来，两个拐弯，照样算连上。

少了这圈空格，边界上的图就少了一整条绕行路线，很多实际能连的组合会被判成连不上。

建这张表的代码在发牌函数里：

逐行看：

  • var C=cols+2, R=rows+2;：var 是声明一个变量，一行里用逗号可以连着声明多个。C 是这张表的列数，R 是行数，各比棋盘多 2，就是左右各一圈、上下各一圈。用大写是因为下面几行里 c、r 已经被拿去当小写循环变量了，同一个名字不能两用。
  • var g=[];：g 是这张表本身，[] 是一个空数组。数组就是一排格子，按顺序编号，编号从 0 开始。
  • 第三行是两层循环，外层 r 从 0 走到 R-1，每一轮里层 c 从 0 走到 C-1，row.push(0) 往一行的末尾塞一个 0，g.push(row) 把这一行接到表的末尾。循环跑完，g 是一个 R 项的数组，每一项又是一个 C 项的数组，这就是二维数组：数组的元素还是数组。取值写 g[r][c]，读第 r 行的第 c 个。
  • 这里的 0 是「空格子」的意思，见下一节。
  • 最后两行填图。deck 是一副洗好的牌（第二篇讲怎么洗），k 是发到哪张的计数。r1 从 1 到 rows、c1 从 1 到 cols，正好是那圈空格围起来的内部区域。g[r1][c1]=deck[k++] 里的 k++ 是「先用当前值、再自增」，等价于取 deck[k] 然后 k=k+1，于是一行一行地把牌填满内部区域。

外圈那一圈格子从来不会被写入任何图，也从来不用清空，这就是「绕外圈」能成立的物理原因。

另两个游戏的棋盘：不要外圈的普通表

美图消消乐和记忆翻牌的棋盘就是一张 行数 × 列数 的普通二维数组，没有外圈，行号列号从 0 开始。

这不是偷懒，是玩法不需要。外圈是为「连线绕到棋盘外面」服务的，只有连连看有这种规则。美图消消乐的消除只看横竖方向上紧挨着的几张图，紧挨着这件事只发生在棋盘内部；记忆翻牌更简单，翻牌配对只比较两张图编号是否相同，跟位置毫无关系。给它们也加一圈，等于修一条谁都不走的路，白占屏幕还得多留神别把边界条件写错。

表里存的值：0 是空，正整数是图案编号

三个游戏的 g[r][c] 都遵守同一套约定：

值 含义
0 空格。连连看的外圈与已消格、消消乐已消格都是 0
1 到 30 这张格子的图是哪一种。连连看与记忆翻牌里同编号成对出现
-1 消消乐的掉落物（M3_DROP）：重物，从顶行沿出口列落下，不参与匹配与交换，只有落到最底行才被收集

判定「两张是不是同一张图」，三个游戏都是第一步比编号：连连看比两张的编号是否相等（第三篇），记忆翻牌在 memTap 里比 M.g[a.r][a.c]===M.g[r][c]，美图消消乐找同号连排。都不用去比像素、也不用管图片文件叫什么名字。

编号与图片文件的对应关系写在生成图块元素的那行：编号 f 对应 img/image + (f-1) + .jpg，也就是编号 1 用 image0.jpg，编号 30 用 image29.jpg。之所以不是编号直接当文件名，是因为图片是从 0 开始编号的一批素材，而代码里 0 已经用来表示空格，编号必须从 1 起，两套编号差了一个 1。

素材总数记在一个常量里，与方向表放在一起：

DIRS 下一节单说。NFACE 是「素材一共准备了 30 种」这条事实的记号，写在代码里备查，发牌并不读它：每关用前几种由关卡表里的 f 决定，编号越界的图不会发出来。img/ 目录里如果缺某一张，图块会在生成时退化成占位的数字，见第五篇。

四个方向 DIRS

每一项是一对数字 [行变化, 列变化]，把当前位置加上一对就得到相邻格子：

项 含义
[-1,0] 行减 1，往上一格
[1,0] 行加 1，往下一格
[0,-1] 列减 1，往左一格
[0,1] 列加 1，往右一格

只有四个，线段只有横着走和竖着走两种形态。判定连线时反复用到这四个，用法是 cur.r+DIRS[d][0] 与 cur.c+DIRS[d][1]，见第三篇。

另两个游戏没有这张方向表。美图消消乐找「横着或竖着连排」用的是直接沿行、沿列扫描（第三篇的 m3FindGroups），不需要「从某格向四个方向试探」这个动作；记忆翻牌压根不看位置。方向表是连线玩法的专用工具，玩法不同，数据结构跟着不同——这也是三个游戏各自一套函数的原因之一。

关卡表 LEVELS

二十行，一行一关：

{c:6,r:4,...} 是一个对象。对象是一堆有名字的值，靠 名字: 值 成对写，用点号取值：level.c 拿到 6，level.t 拿到 150。数组里放对象，就是「一关一条记录」。

键 含义 用在哪
c 棋盘列数 发牌、首页那行说明文字
r 棋盘行数 同上
f 这一关用前几种图案 发牌时决定图案编号的循环上限
t 限时，单位秒 倒计时起始值、首页文字、剩余时间的奖励
h 提示次数 提示按钮的次数与禁用条件
s 重排次数 重排按钮的次数与禁用条件
grav 聚拢方向，可选 只有第 15、18、20 关有，消除后图块往这个方向靠，见第四篇

几个从这张表里能读出来的取舍：

  • c 与 r 的乘积一定是偶数。牌要成对发，总数必须是偶数，所以这张表里每一关的行列数都凑成了偶数张。乘积一旦是奇数，最后一张会落单，永远消不掉。
  • c 与 r 是设计目标，不是最终行列数。发牌时会在「乘积等于这个牌数」的所有因数分解里，挑一个在当前窗口下放得最大、又最接近设计列数的组合，挑法见第五篇。牌数始终不变，变的只是横竖怎么分配。
  • 行列上限压在 15 列 12 行（最后一关 c:15,r:12，180 张）。手机竖屏太窄，列数一大每格就被挤得过小，所以封顶之后不再加格子。限时跟着牌数一起放宽（第一关 150 秒、最后一关 640 秒），牌越多给的时间越长，难度靠图种和提示/重排次数去压，而不是靠把格子挤小。
  • 从第一关到最后一关，牌数（c*r）和图案种类（f）一起涨。图多、花样也多，难度自然上去了，但真正卡人的是后两项：h 从 5 一路降到 1（第 14 关起就只剩 1 次提示），s 从 3 降到 0。第 18、19 关 s:0 意味着没有重排次数，排成死局只能重玩；最后一关反而给回 s:2，因为它的随机聚拢更容易把牌推成死局，留两次重排兜底。
  • 第 15、18、20 关多了一个 grav 键：消除之后剩下的图块会往指定方向聚拢（左、中、随机），等于每消一对棋盘就重新挤一次，连线路线随之改变。这是后期关卡的特殊规则，机制与代码在第四篇细讲。
  • 关卡表里没有图的名字，只有编号。换一批素材只要把 img/ 目录里的图片换成同样编号的文件，这张表不用动。

(best?' · 最高 '+best:'') 也是三元表达式，形如 条件 ? A : B，条件成立取 A 否则取 B，这里的意思是「这一关有过最高分才追加那半句」。

另两张关卡表：M3_LEVELS 与 MEM_LEVELS

美图消消乐和记忆翻牌各有自己的关卡表，都是「数组里放对象」，但三张表的字段并不通用：消消乐 30 关，一关写「棋盘、同屏元素数、步数、目标类型与目标量、特殊机制」；翻牌 20 关，一关写「棋盘、图种、总牌数、展示时间、配对限时、允许犯错次数」；连连看的 LEVELS 是 20 关的限时表。读代码时最容易在「同一个键名含义不同」这里栽跟头。

美图消消乐：M3_LEVELS（30 关）

一条记录长这样（首尾各举一例）：

键 含义
c / r 棋盘列数 / 行数，7×7、8×8、9×9 三档，开局就是最终形状
f 同屏元素数，5 到 8 种；m3FacePool 会把本关的「指定元素」在发牌池里多放几份，种类数仍是 f
m 步数，一次有效交换减 1
type / gt 表格里的目标类型与目标量原文，只用于首页说明和 HUD 标题
g 真正驱动判定的目标数组，见下表
sp 特殊机制原文（冰块 / 木箱 / 木箱阻挡 / 冰块+木箱 / 限洗牌2次）
h / s 提示次数 / 手动洗牌次数；第 30 关 s:2 就是「限洗牌 2 次」

g 里每条是 {k, n, t}：n 是目标量，t 是指定元素在 G.targets 里的下标，只有 elem 用得上。

k 判定方式
elem 消掉指定编号的图案累计 n 张；「消除两种元素 各N」写成两条 elem，分别指向两个不同编号
drop 收集掉落物 n 个：金色星块从顶行沿出口列落下，只有该列本次交换消过图案才下沉（一次交换最多 2 格），落到最底行（金色边）才被收走
ice 打碎 n 块冰：半透明冰块所在格被消除时打碎
crate 打碎 n 个木箱：相邻格被消除时打碎
obs 冰块 + 木箱合计打碎 n 个，用于综合目标里的障碍项

多条目标要全部达标才过关。G.prog 与 g 一一对应记录进度，m3GoalsDone() 逐条检查；混合目标、综合挑战、终极综合都只是把上面几种拼进同一个数组。

记忆翻牌：MEM_LEVELS（20 关）

键 含义
c / r 列数 / 行数，按「A×B = 列×行」解释；乘积 p 就是总牌数
f 图种，恰好等于对数 p/2，每种图正好一对两张
p 总牌数，等于 c*r
rev 展示（亮牌）秒数，开局所有牌正面朝上这么久
t 配对限时秒数，0 表示不限时；亮牌结束后才开始倒数
e 允许犯错次数，0 表示不限；第 e+1 次配错即失败
h / s 提示 / 重排次数

第 1~4 关 t:0, e:0，既不限时也不限犯错；第 5 关起两条约束同时生效，越往后时间越紧、容错越少。

三张表放在一起看，同一个字母在不同表里含义完全不同：t 在连连看是限时秒数、在翻牌是配对限时秒数，消消乐则没有 t；m 只在消消乐里是步数，翻牌用 t 和 e。读代码永远要以「这张表自己那一栏的解释」为准，不能想当然。

一局游戏的当前状态：S、G、M

代码里没有第二份棋盘。每个游戏的所有可变成量集中放在一个状态对象里，开局那一刻整个换成新的。连连看的叫 S：

属性 含义
lv 本关的参数表，就是 LEVELS 里那一行
no 第几关，从 1 开始
g 那张大一圈的棋盘表本身
rows / cols 棋盘的行数与列数，不含外圈
cell 一格多少像素，第五篇算的就是这个数
total 开局共有多少张图
left 还剩多少张没消
time 剩余秒数，每 0.1 秒减一次
hint / shuf 剩余的提示与重排次数
score 本关分数
sel 当前选中哪张，没选中是 null
locked 是否正在播放消除动画，用来挡住新的点击
grav 本关聚拢方向，没有该规则时是 null

null 是「这里没有东西」，不是 0、也不是空字符串。locked:false 里的 false/true 是布尔值，只有这两个状态，专门用来当开关。

var S=null, timer=0... 那一行里：timer 是定时器的编号（第七篇用它停计时），lastMatch 与 combo 管连续消除的加分。S=null 的含义是「开局前根本不存在任何一局」，所以点击处理进来第一件事都是检查 S 在不在，见第七篇的 tap。

同一段里还剩一个 runBase=S.score，赋值之后没有任何地方读这个变量，属于遗留写法。留着不影响运行，但别按「本关起始分」去理解计分。

美图消消乐与记忆翻牌的状态对象与 S 同构，差别集中在「约束」这一栏：

属性 连连看 S 消消乐 G 翻牌 M
约束值 time 剩余秒数 moves 剩余步数 time 配对剩余秒数（t:0 时不计时）、err 已犯错次数
过关条件 left 减到 0 m3GoalsDone()：prog 每条都达到 lv.g[i].n left 减到 0（剩余对数）
进度条画什么 剩余时间的百分比 各条目标进度的平均百分比 亮牌阶段画亮牌比例；配对期限时画剩余时间比例，不限时画已配对比例
盘面层 g 数字棋盘（带外圈） g 图案棋盘 + ov 障碍层 + prog 目标进度 + targets 指定元素 g 数字棋盘 + reveal 亮牌剩余秒数 + errLim 犯错上限
特有属性 total pool 加权发牌池、dropNeed / dropGot 掉落物计数、exitCols / nextDropCol / clearedCols / sinkUsed、shufUsed 已洗牌次数、over rev 亮牌总秒数、flips 翻牌次数、streak、first、busy

三个对象都有 locked 或等价的 busy：动画播放期间挡住新的点击。M.first 记录第一张翻开的牌，M.streak 记录连续配对成功次数。胜负确定时消消乐用 G.over、翻牌用 M.over 关闸，并停掉各自的闹钟；翻牌的两个闹钟是 revT（亮牌）与 pairT（配对限时）。

自测

  1. 连连看的代码表为什么比棋盘横竖各多两行两列？少这一圈会怎样？ 答：这一圈是留给连线绕棋盘外用的通道。少了这一圈，边界上的图就没有绕行路线，很多本该连得上的组合会被判成连不上。
  2. 美图消消乐和记忆翻牌的棋盘为什么不需要外圈？ 答：外圈是为「连线绕到棋盘外」服务的。消消乐只看相邻格子连成排，翻牌只比两张图编号，都不需要从棋盘外绕路。
  3. g[0][3] 上的值在连连看里有可能不是 0 吗？ 答：不可能。第 0 行是外圈，填牌从行 1 开始，外圈永远是空格。
  4. 表里存的值是 7，代表什么？ 答：这张格子的图是第 7 种图案，对应 img/image6.jpg。三个游戏都遵守这个约定；区别在连连看和翻牌里同编号恰好两张，消消乐里同编号随机分布、可能多于两张。
  5. 连连看关卡表里的 s:0 是什么意思？ 答：这一关的重排次数是 0，重排按钮一开始就是禁用状态，排成死局只能重玩。
  6. 关卡表里写着 c:15，手机窄屏上也一定是 15 列吗？ 答：不一定。c 是设计目标，实际行列由牌数的因数分解在当前窗口里重新挑，挑法见第五篇。
  7. 三张关卡表里的 t 各是什么？ 答：连连看的 t 是限时秒数，记忆翻牌的 t 是配对限时秒数（0 表示不限时），美图消消乐没有 t——目标写在 g 数组里，gt 只是给玩家看的原文。
  8. MODE、S、G、M 为什么各设一个，而不是合成一个大对象？ 答：分开后每个游戏只操作自己的状态，点击分发只需要一次 MODE 判断；合在一起则每个函数都要面对另外两个游戏的字段，改一处容易碰坏别处。
  9. 消消乐的「终极综合」为什么写成三条 g 记录？ 答：「元素50+掉落3+障碍15」是三个互不替代的目标，G.prog 逐条记进度，m3GoalsDone() 要三条都满才过关；合成一条就没法分别显示进度。
  10. 第 30 关 s:2 限的是哪种洗牌？ 答：只限玩家手动按重排按钮。死局时的自动重排是保底机制，不消耗这 2 次，否则玩家会在不知情时用光机会。
  11. 翻牌第 5 关 t:420,e:8 里的 420 秒从什么时候开始数？ 答：亮牌 rev:12 秒结束、牌全部翻面之后才启动 pairT，亮牌时间不占配对限时；第 9 次配错才判负。
