Hexo 本地后台

发表于2026-10-22|更新于2026-10-25|学习建站
|浏览量:

这是什么

给 Hexo 源目录配一个只在本机跑的编辑后台，管到 source/ 的全部内容加上根目录的配置文件：文章、草稿、独立页面、主题自定义集合、source/_data/ 里的数据文件、scaffolds/ 里的模板、静态资源都能增删改；_config.yml 与主题配置铺成中文标签的表单。构建和部署仍在命令行做，后台不落 public/，也不执行任何 hexo 命令。

覆盖面靠目录约定自动发现：source/_posts/ 是文章，source/_drafts/ 是草稿，source/_<名>/ 是主题自定义的集合，其余 markdown 与 html 文件是页面，剩下的都归资源。后台不认识的 front-matter 键、读不懂的配置结构，一律降级成原文编辑而不是拒绝。将来站点加集合、加配置键，后台不用改代码，这是「通用」在这里的全部含义。

出发点是把「改一篇内容」的代价压到最低。命令行侧手工改一篇要同时盯住 front-matter 的键名与引号风格、分类要写成数组、嵌套缩进要对、配图要先算出站内相对路径，任何一处漏了都要等构建才发现。源目录不是 git 仓库时，改坏了没有版本兜底。后台把这些约束变成界面里的选择与保存时的固定动作，手工编辑仍然全部有效，两边写的是同一份文件。

零依赖是这条链的前提。只用 Node 内置的 http、fs、path、crypto，不引 express，不引富文本编辑器，package.json 里不加 scripts 项也不加依赖。YAML 解析复用 hexo 安装里自带的那份库，取不到就退化成「只给原文编辑、不铺控件」，写回与校验规则不变。总共两个文件：tools/admin/server.cjs 是接口与写盘，tools/admin/ui.html 是整张页面，样式、图标、脚本、中文字典都在这一个文件里。拷进任何 Hexo 源目录都能直接起，不需要装东西，也不会与主题的依赖表打架。

起法

启动参数

启动后终端只打一行 admin on http://127.0.0.1:43210。与 hexo server 是两个进程，可以同时跑；后台不依赖 hexo server，起不起都能用。

六个视图共用一套组件，没有第二套列表、没有第二套表单：

页面与出口

跳转有四条主线：概览进集合列表、列表进表单、表单回集合列表；列表进资源详情、资源详情回资源列表；侧栏在任一页切集合或配置，切集合与切配置都走真实跳转，地址栏跟着换，刷新仍落在同一页；配置页第二层右侧目录在段间直接跳，搜索命中任意一层键时直接跳到该行。后台是工具页，不需要站点级的信息架构，铺导航就会开始铺样式，那是主题该管的事。编辑页里也不铺分类和标签的跳转链接，那些目标在站点前台已经存在，后台里只作筛选条件；同一个跳转目标铺两遍只会让页面更吵。

侧栏固定 216px：品牌在顶，下面两组（内容：概览与各集合，资源排在末尾；站点：配置），每项一个图标、名称与条目数，当前页用强调色浅底加左侧 2px 竖条；侧栏贴住视口、自己滚动。窗口窄到 1100px 时侧栏改成一行横向滚动的导航条，品牌留在左侧，分组标题与条目数收起，页头与工具条不再粘顶，避免两层固定条叠在一起。列表在 900px 以下收起标签列，700px 以下收起路径、分类、更新三列并把分类或路径放到标题下面一行，条目计数同时收起。375px 下导航条照样一行、可滚到「配置」，「新建」与「保存」不收缩，480px 以下页头文件名收起。

source/_drafts/ 草稿 同上，date 允许改，列表里标「草稿」，多一个「发布」动作

集合与形态

归类按表中顺序取第一条命中的规则：_posts、_drafts、_data 先于通用的下划线目录，下划线目录先于页面，页面先于资源。页面目录页的 index 后缀在界面上折叠成目录名，about/index 显示成 about/，读写仍按真实路径。

layout 的判定顺序是 front-matter 的 layout 优先，其次目录约定（_posts 为 post、_drafts 为 draft、其余为 page），最后取 _config.yml 的 default_layout。独立 .html 页面必须自带 layout: false，这一项在页面表单里作为受管键给出来，后台不隐式补写。带 front-matter 的 .html 一律走原文态：这类页面常带 <script>、<style> 与整页结构，塞进 contenteditable 会把脚本当可编辑内容、保存时按段落规则重排，风险大于收益。

新建命名跟着站点配置走：文章与草稿按 _config.yml 的 new_post_name 展开，:title 换成 slug，日期类占位取当前时间；页面固定落在 <slug>/index.<扩展名>，扩展名跟该集合里已有的同类条目一致，没有就先建 .md。

草稿发布属于数据层：文件从 _drafts/ 移到 _posts/ 并按 new_post_name 补日期，不跑任何 hexo 命令。移动不是删除，所以不进 .trash，界面提示写清新旧两个路径。

front-matter 原文区

表单只管受管键，其余键给一个原文编辑区，显示磁盘上那段 YAML 原文，不重排、不改引号风格、不补默认值。保存时的合并规则按顺序执行：以磁盘原文为底；受管键逐行替换成表单值，原文里与受管键同名的行位置不动，界面上标一句「该键由表单管理」；表单没有、原文有的键原样留在原位；原文没有、表单新增的键追加到末尾。

原文区那段被改坏时拒绝保存并给行号，不做「尽力修复」，两类都拦：围栏不成对、缩进异常、键名解析不出，回 front-matter 第 N 行解析不了；整段能解析但不是映射形态时回 front-matter 第 N 行要写成 键: 值。后一条是必要的：title 缺冒号 在 YAML 里是一个合法标量，只按「能不能解析」判定会静默把整段 front-matter 写成一个字符串。表单值合并进来的那一版再过一次同一道判定。

配置层

用后台的人未必读得懂 YAML，也未必打得对缩进。配置项铺成中文标签加一句中文说明的表单，改一个开关不用去文件里找那一行、再担心删掉了别人的注释。配置文件是全站生效的，写坏一次站点就起不来，所以写回必须只动那一段，不做整份重写。

文件发现

文件 角色 后台形态
根目录 _config.yml 站点配置 表单，可写
根目录 _config.<主题名>.yml 主题覆盖配置 表单，可写，优先级高于主题目录里的同名文件
根目录 _config.<其它名>.yml 名字与站点配置里 theme: 指的主题不符 表单只读，标一句 这一份不参与构建：hexo 按主题名找覆盖文件，这类文件改多少遍都不进站点；起站点或构建时显式带 --config 指定这类文件的除外，后台看不出有没有带
themes/<名>/_config.yml 主题自带配置（仓库里那一份） 表单，可写；被根目录覆盖文件占用的那一条键标一句「根目录已覆盖」
themes/<其它名>/_config.yml 没被启用的主题自带配置 表单只读，同样标 这一份不参与构建
node_modules/hexo-theme-<名>/_config.yml 主题自带配置（装出来的那一份） 只读展示，配一句「主题更新会覆盖这一份，改根目录的那份」

配置文件与角色

清单不写死文件名，扫根目录、themes/ 与 node_modules/ 三处得到。同一条键在多份文件里都有时，行内标出实际生效的那份，判定按加载顺序取后者。主题名从站点配置的 theme: 读，读不出（没有站点配置或那份解析失败）时不标 不参与构建，退回按可写处理。

只读那几份的值照全部显示，改动入口一个不渲染：每一行的「删」「改原文」「加一项」、列表项的上下移与删除都不出现，末尾追加那一段也不出现，输入控件与保存按钮全禁用；服务端再挡一道，提交给 这一份不参与构建 或 这一份改在根目录的覆盖文件里，文件字节不动。

「根目录已覆盖」按完整点路径逐条判，不按顶层段：主题自带配置里某个叶子的路径在覆盖文件的解析树里同样存在才算被覆盖，父段出现在覆盖文件里不算该分组下每个叶子都被遮，覆盖是按键深合并的，段里有几条就遮几条。这一条标注只显示在带值控件的行上，分组行、凭据行、主题默认值补出来的行都不带——分组行带上这条标注会被读成整段都被覆盖，那正是按段判定的说法。差别在覆盖文件只写了几条的站点上才看得出：按段判会把没写的那几条也标成已覆盖；覆盖文件是整份副本的站点上，两种判法给的是同一个集合。

控件按值的形态给

顶层键按文件里的出现顺序分组，每组一个折叠区。组内每个键一行：中文标签、键名原样小字、值控件、一句话说明。控件按值的形态递归给，嵌套多深就展开多深，每一段都同时留着「改原文」入口。

值的形态 控件
布尔 分段开关
关掉是 false、开启是一个数 两段开关加一个整数框；选关闭那一段时框禁用、交出去的是 false，选开启那一段时框里要填正整数
整数、小数 数字输入框，字典给了范围就带上范围
字符串 单行输入框；字典给了候选值的（站点语言、链接样式、图片格式这类）换成下拉

形态与控件

形态判定来自解析出的值，不靠行首正则猜。定位某一行时先由解析值知道这一层有哪些键、列表有几项，再在段内找缩进符合且键名命中这一层键清单的行；块标量里的 CSS 行、注释行不在键清单里，不会被当成配置行。父键行右边只剩一个行尾注释时不算内联值，块式列表与对象数组照样逐项出控件，那一行由写回原样保留。任一层对不上（缩进异常、注释夹在列表项中间、解析值与行扫描条数不符）该段整段退回原文框，标签下标一句 这一段形状对不上，只能改原文，不做半结构化写入，也不拒绝整页。

映射的键名本身就是界面文字——菜单项的键名是显示文字，分类映射的键名是中文分类——所以子键行左边是可编辑的键名框，右边是值控件，末尾一个「删」，组底一个「加一项」，列表项同理。改键名只改这一行的键，值与行尾注释留在原行。原文入口与结构化入口一段一次只走一种：同一段已有叶子改动时再点「改原文」直接挡下并提示 这一段这次只改一种。

写回只动那一段

主题配置文件里注释行的数量与配置行相当，注释就是这份文档，一次保存把注释冲掉等于毁掉这份文件。写回是行级替换：定位该键从起始行到下一个同级键之前的整段，换成新内容，其余行逐字节不动，包括空行、注释、引号风格与数组的流式或块状写法。结构化写入落得更细，只替换叶子那一条键值行；新增项落在该块最后一个同级项之后，块里还没有同级项就紧跟父键行；删除项移除该键那一段，块内注释跟着这一项一起走。

块状列表按槽位写：列表的顺序就是行的顺序，新值与旧值逐项同下标比对，没变的原行一个字不动，变了的只写那一行并保留该行的行尾注释，多的项接在最后一项之后，少的项整行删掉；值从别的行搬过来时（增删与改序都会），原行的行尾注释跟着值走，不留在原位。流式列表整体重写那一行，逐项没变时连这一行都不碰。值形态跟着原文走，原来写成 '值' 就继续写 '值'，原来是裸值就裸写。文件里没有的新键追加到末尾。

保存一次提交该文件里所有改过的键，逐段替换完再落盘，写文件仍是同目录临时文件加 rename 原子替换。写前把整份文件解析一次，解析不了直接拒绝并给行号；写后再解析一次，断言目标键的值等于表单提交值，任一步不过就不写盘。

主题默认值里没写进文件的键

主题脚本目录里那份默认配置（scripts/common/default_config.js 这类）会被并进主题配置，站点读到的值是「默认值 → 主题 YAML → 根目录覆盖」三层合出来的。默认值里有、两份 YAML 里都没有的键，表单只按文件生成就看不见这一行，这类键改不到。这一类补进根目录覆盖文件的表单：取启用主题的那份默认配置，按完整点路径补在同一个父段下（父段在文件里也没有就先铺这一层的分组行），值先显示默认值，标签下标一句 这一项文件里没写，值是主题默认，「删」与「改原文」都不给、键名框不可编辑。动过才落盘，走「文件里没有的新键追加到所属段末尾」那一条，父段是新建的就把父键行一起写进去；一个字没动就不写，文件照旧不含这些键。落盘之后重新读取，这一行就是带行号的普通行。补项同样过凭据判定，默认值里名字算凭据的键不铺出来。默认值里某个键是个分组、文件里同名的却是一条列表或一句话时，这一行不铺子项，只标一句 这一段在文件里是别的样子，主题默认在这一项下面还有几项，要加就改这一段原文，这一段里的默认项走原文那条路。同一个位置已经有的键再提交一次，服务端拒掉并给 这一项已经在文件里了。默认配置读不到（主题不按这个约定放文件）就整段不补，表单退回只列文件里已有的键。

中文标签四级退回

标签与说明来自源码里的一份字典，取中文按四级退回：点分路径字典（aside.display.archive 这一级）→ 键名词典（按键名本身查，任何 YAML 配置通用）→ 该键在文件里正上方的注释 → 键名原样并标一句「这一项没有中文说明」。主题与 hexo 的配置文件自带的是英文注释，第三级只在注释含汉字时采用，那种注释不进界面。补齐字典靠改那一段数据，一行一个键，不改逻辑。

词典只提供标签与说明，候选值与取值范围来自另一份按路径记的字典，且只按完整点路径命中、不逐级退回：退回会让同名的嵌套键继承别人的候选值，主题里 code_blocks.language 是个开关，不该拿到站点 language 那组语言候选。布尔之外还有一个裸词的键（code_blocks.shrink 的 none、aside.card_categories.expand 的 none）标成三态，界面给三段开关，段名写这个值在主题里的作用：默认收起 / 展开 / 展开与隐藏按钮。有候选值的那类键给下拉，每个候选写成 值（中文含义），与值本身重复的括注不写；当前值不在候选里时那一项也出现在下拉里并被选中，改回候选内的值之后这一项消失。字典没铺到的键不做取值判定。按数用的键（每页条数、相关文章条数、深色模式切换时刻、侧栏卡片的排序位）另记一份数值声明，同样只按完整点路径命中：这类键当前留空也给数字框，留空给文本框的话一句话填进去就是一个认不出的值。关掉是 false、开启是一个像素数的那类（代码块限高）单独声明，出两段开关加一个整数框，两种形态切换写回的是同一行。主题把值当成带单位的 CSS 声明用的键（字号、头图高度、图标偏移、按钮间距）不进数值声明，仍是文本框，说明位把可写形态和例子写出来：这类键收下一个不带单位的数字，样式表里那条声明直接失效，构建一行错都不报。

凭据项与部署段

deploy 整段、secret，以及名字里带 token、key、password 的键，不给控件、不回显值，只显示键名所在行的定位。判定不分层级，任何深度里出现这类键名都按同一规则处理；键名按词切分后再比对，api_key、apiKey、apikey、appId 都算，keywords、keyboard 这类不含独立 key 词的键名不算。这类键所在的那一段连带失去整段入口：原文区不出文本框、「改原文」与「删」两个控件都不出现，这一段里其他键照常逐项用控件改、也照常加新项，落盘时那些行逐字节不动。提示一句 这一段里有凭据项，不能整段改原文。后台不做部署，这一段的正确性由人工负责。

校验与生效

配置文件没有必填项，允许任意键留空。类型不符时给一句话并拒绝写入，提示落在同一行的提示位上、不带键名：这一项要填整数、这一项要填数字、这一项要填日期，加上 root 要以斜杠开头和结尾、url 要带协议 两条按字典判定。开关与三段开关都是分段控件、不给自由文本，所以没有「格式不对」那一类文案；三段里那个裸词按值的形态判定，含空格、冒号、引号、注释符的一律拒并回 这一项要改原文，判定不看键名，没有键清单。写回时提交的是布尔就裸写 true、false，提交的是那个裸词就裸写那个词，两种形态互相切换仍是同一行的行级替换。数值项交空串或缺值同样拒掉、回 这一项要填整数，空提交不等于 0；把框清空回原来的空样子不算改动，提交前那一项整个撤掉。「关掉是 false、开启是一个数」那一类的正整数判定在界面发请求前做，服务端没有路径字典，看不出某个整数位置该不该收布尔。

配置文件不被监听，改完不会即时反映到 hexo server，也不动产物。保存后的提示只有一句：已写入，重启 hexo server 才生效。后台不代跑、不拼命令。

配置第二层右侧一栏目录，列出全部顶层段，栏宽 240px、字号 14px，点一段跳到那一段；搜索框按关键字命中任意一层的键，结果里带上级段路径，点一条直接跳到那一行；滚动时当前段在目录里高亮，「到顶部」「到底部」两个按钮直达两端；目录自己滚动，不把页头挤出视口。1100px 以下目录变成表单上方的折叠块，默认收起。

另有一类是改了也进不了产物：主题样式里那条规则是个与关系，另一份文件里的开关不配合，这一项无论写成什么都被短路掉。这类跨文件门控由界面侧记一条声明（这一项的点路径 → 若干条依赖，每条写依赖哪份文件里的哪一条、什么值算通得过、不配合时怎么说），声明的依据是主题源码里那一行判定；渲染时界面按声明读那一份文件的当前值逐条比对，把当前不配合的那几条并成一句显示在这一项的说明位上，保存成功的提示也带上这一句。依赖那一条在那份文件里读不出值时不算不配合。门控只写声明过的那几条，不推测别的键，服务端不参与这类判定。

分类与标签

候选集合只从磁盘扫描来：把带分类的集合里出现过的分类聚合成候选，每次请求列表时重算，不落库。层级深度取候选里出现过的最大深度，选择器按该深度级联；一个分类都没有时，第一级只剩一个输入框。一篇文章可以选多条完整路径，已选的行显示成「父级 › 子级」形态，右侧一个「删」字。

分类是级联芯片，选项直接铺成可点的一排，点一下就选中，再点取消，不设「打开选择器」的按钮。弹层里翻树要点两次才能落定一个值，芯片一次到位。新子分类在底部一行输入框里创建：填名字、选父级、点添加，芯片立刻出现在候选里并被选中。没保存进任何文章的候选，重新打开表单就消失——分类的真相只有源文件这一份，多存一份就会不一致。

标签是一排芯片加一个输入框，已有标签点选，新标签输入后点添加。标签没有层级，不做父子约束。分类与标签都为空时允许保存，写成 categories: []。

页面集合没有分类与标签控件：categories 与 tags 由文章处理器赋予，页面里没这两层语义。要按分类组织内容就只能写成文章。

正文编辑器

正文框是 contenteditable 的所见即所得区，不引第三方编辑器。理由是产出格式：后台直接吃块级 HTML 这个形状、吐这个形状，中间没有转换层。第三方富文本编辑器自带一套 HTML 方言与样式类，接进来第一件事是写双向转换，转换写不对就污染源文件。

打开时把源文件正文解析成块结构，保存时把 DOM 序列化回一行一块。顶栏的「所见 / 源文」切到一个等宽纯文本框时直接改源文本，切回所见时重新解析，两种形态共用同一份待保存内容。Markdown 正文这一种例外：编辑区换成只读预览，工具条收起，切换标签显示「预览」，改字走「源文」栏，细节见「写盘形态」。

产出形状跟着站内已有正文走，侧栏一个芯片切换「块形状」与「裸标签」：默认按扫描结果判定，站内正文里出现过 wp-block-code 或 wp-block-table 就用带块名的形状，纯 Markdown 站用裸标签。切换记在浏览器本地，不需要改代码，也不为此加一份配置文件。

工具条用图标不用文字胶囊，一组一个动作，横向一排放得下十来个动作；文字胶囊会把工具条撑成两行。按下态由当前选区与光标所在块决定，光标在单元格里时才出现表格那四个动作。

工具条动作

块级动作一律做成开关：标题、引用、列表、代码块都能再点一次退回正文。「只能进不能出」等于把改坏的段落留给源文态手修，那还不如不用后台。

标题是一个下拉，七项：正文与一级到六级，弹层与表格尺寸选择器共用同一套机制，当前光标所在的层级在菜单里高亮，按钮上的字标跟着变成 H2、H5 这样的当前层级号，落回正文只剩一个 H。层级不做限制，没有「只能从 h2 起」的拦截——拦在界面上的规则一旦和站内既有文章打架，就只能靠源文态绕。

h1 与页面标题同级：主题通常把文章标题本身渲染成 <h1>，正文再出现 h1 就是一页两个 h1。用哪一级由写的人决定，后台只负责把这一级的样式显示成站点实际会渲染出来的样子，编辑区与前台不一致时「所见即所得」就只是名字好听。对齐做法见最后一节。

点按钮的瞬间选区会被浏览器清掉，命令落到空选区上就会「按下去没有反应」。图标按钮在 mousedown 上阻止默认行为，并在失焦前记下 Range，命令执行前先恢复记下的选区。所有提前返回的分支都给一句话提示，不做静默无操作。

快捷键只有三个：⌘S 保存、代码块内 Tab 插两个空格、代码块内 Enter 补一个换行。空代码块与空引用里按 Enter 直接退回正文段，和空列表项两次回车退出是同一手感。键盘事件的目标元素永远是可编辑宿主，不是光标所在的块，判断光标落在哪个块里只能按选区位置取，靠事件目标判定会整条分支静默落空。工具条右侧的字数是去掉空白后的字符数。

编辑页左侧一栏大纲，按标签层级收集正文的 h1–h6，所见态直接读编辑区 DOM，源文态与原文编辑按行解析 Markdown 的 # 标题与 HTML 标题标签。每条按层级缩进，点击把标题滚到视口靠上位置并把光标放到标题开头；源文态移动文本框选区，不切形态。大纲随输入重算，滚动正文时高亮当前标题。标题栏给标题数与「收起」：收起后只留一条 34px 宽的竖条写着「大纲」，点竖条展开；折叠状态存本地，下次打开保持。正文没有标题时整栏不出现，编辑区分栏回到正文加元数据两栏。1360px 以下大纲落到正文上方的整宽折叠块，标题栏常驻、列表最高约三分之一屏；1100px 以下元数据栏也落到正文下方，编辑区变成单栏。

正文框、front-matter 原文框与配置原文框都是固定尺寸，只有内部滚动，没有拖拽改大小的把手；侧栏、元数据栏与大纲各自在视口内滚动。

配图

三个入口共用一条上传通道：工具条上的图片动作、正文里直接粘贴图片文件、侧栏封面上传。前两个把文件读成 base64 POST 到 /api/upload，服务端解码落盘到 source/uploads/<年>/<月>/<文件名>，返回站内路径再插进正文；封面只取返回值写进 cover，不进正文。文件名冲突时追加时间戳。粘贴路径会阻止浏览器把图片转成 base64 内联，落盘后正文里只有站内路径。体积判定是服务端一个常量，超判定的直接拒绝并回一句话，要改就改那一行，不为此加配置文件。

从资源页上传时落进当前所在目录，参数只接受 source/ 下的相对路径，路径规范化后断言仍在 source/ 内，越界返回 403。

不引 multipart 解析库，走 base64 JSON 是为了守住零依赖，代价是大图内存驻留，判定阈值先拦在前面，请求体上限又设在一个明显高于配图判定的值，超限直接断连接。一条通道三个入口，也省掉「同一张图从两个入口进去落成两种结果」。

编辑区能看到图，是因为后台自带一条静态资源路由：除页面路由与 /api/ 以外的请求路径直接当作 source/<路径> 读盘返回，扩展名白名单限定图片、样式、脚本、字体与音频，响应头 Cache-Control: no-store。正文里写站内相对路径就能加载，不需要为了看图再起一个 hexo server。目录名不写死，站点将来新增 /css/、/js/、/media/ 这类资源目录，编辑区照样能加载。

资源页每行给路径、类型与引用次数，图片行另给一张 56×42 的缩略图，比例不拉伸，非图片行预览位留空；缩略图按需解码，滚进视口才加载。引用次数等于所有条目正文里出现该站内相对路径的次数，按出现次数计，不只按文件计。删除走 .trash，被引用大于 0 时提示里带上引用数，但仍允许删。改名不做——引用散在各篇正文里，改名不会跟着改写，这是写下来的边界。

写盘形态

保存时先重新读一次磁盘再合并写入，而不是把打开页面时的内容整份覆盖回去。原因是有些插件会在构建时回写 front-matter，用内存里的旧快照覆盖会打回旧值。后台管理的键按表单结果写，其余键一律原样保留，不排序、不改写、不补默认值——源文件里可能有后台根本不认识的键。

字段模型

文件名编辑时只读，是因为 permalink、插件生成的短链与已分发的链接都挂在文件名上面；改名在后台里等价于「新建加删除」，做成一个按钮反而掩盖了这一步的代价。

正文一行一个块，块之间空一行，围栏与正文之间一个空行。写文件用同目录临时文件加 rename 原子替换，避免 hexo server 监听时读到写了一半的文件。

块之间那个空行是承重的，不是排版偏好：少这一个空行，marked 会把围栏代码块内部的行当成新段落开始解析，产物里就多出看得见的 <p> 字面量。序列化按块 join 时补这一个空行。

序列化只处理结构，不改文字：块级元素嵌在 <p>、<span>、<a> 里时向外提升；引用块里套 <p>、<ul> 是块级 HTML 正文本来的写法，原样保留不往外搬，否则一次保存就把引用拆成空壳加正文。粘贴带进来的 Apple-* 临时类与无样式 <span> 剥掉，<img> 统一补成自闭合。代码块内部浏览器给的是 <br>，落盘前换回真换行。

纯 Markdown 写法照样渲染，后台不是渲染的前提：## 出带锚点的二级标题，围栏代码块直接进 hexo-util 高亮，管道表格出 <table>，判定口径与这套 HTML 块写法一致。

后台这一侧按正文形状分两种形态。一行一个块级标签的走所见即所得。带 Markdown 记号的走只读预览：这类正文里的反引号、围栏、竖线不是标签，塞进 contenteditable 会把反引号内的 HTML 片段当成真标签解析，序列化回来就不是磁盘上那份。预览用一套自带的小解析：围栏出 <pre><code>，# 出一到六级标题，管道行出带 <thead> 的 <table>，> 出引用，-、*、1. 出列表，行内反引号按字面转义。判定取两个条件的交集：既不像一行一块的形状、又确实带 Markdown 记号，才切预览；纯文本老正文两个条件都不满足，照旧可编辑。多行 <pre> 与缩进式 HTML 的收尾行（</blockquote>、</tbody></table><figcaption>）按标签嵌套深度算延续，不算 Markdown 痕迹。

只读预览承担的是「在后台核对前台效果」这一件事：结构逐项与产物一致，改字仍然走源文栏，写回磁盘的就是源文本框里的内容，不经过 DOM 往返。要做的是不损坏，不是替 Markdown 编辑器代劳。

与插件、hexo server 同跑

会回写 front-matter 的插件不止一个，hexo-abbrlink 是一例：该插件在处理文章时补生成用的键、把引号改成单引号、把流式数组重排成块状两行。hexo server 运行中只要新建或改动一篇就会触发，不需要手动跑 hexo g。重排只改形状不改值。

因此外部改动保护不能按原始字节比。后台把磁盘文件重新解析成同一个模型（受管键加非易变额外键）再取哈希：插件重排形状时指纹不变，保存照常通过；真被别的编辑器加了一段正文时指纹改变，保存被拒并提示 文件已被外部改动，请重新打开，磁盘内容不动。打开编辑页时接口就把指纹一起返回，保存时带回去比对。宁可拒绝保存，也不静默覆盖别人的改动。

另一个可见的连带效果：hexo server 会在源文件变动后重新生成并写 public/。后台进程不写产物，源码里没有指向产物目录的写入路径，也不派生子进程；看到产物时间戳跟着保存变化，那是 hexo server 干的。

副本位置

.trash 在 Hexo 根目录，不在 source/ 下，不进产物，站点上不留痕迹。删除是列表进编辑、点删除、确认弹层点确定三步，确认后界面回列表并提示源文件在 .trash。物理删除在这种场景里没有收益：省下的磁盘空间换不回一篇写坏的文章。

边界

不做的部分写清楚，免得照着找：

不执行任何 hexo 命令，不执行构建，不执行部署，保存后也不提示命令；不做第二条构建入口，不落 dist/，不让浏览器成为上线路径；不写 public/、不写 package.json、不写 node_modules/ 里主题自带的配置；不做资源改名与移动；不做拖拽图片进正文；不做多人协作与并发编辑；不做 Markdown 与 HTML 块两种写法之间的互转；不显示、不写入凭据形态的键；配置改动不代跑重启。

产物只由命令行的 clean、generate、deploy 决定。后台这一侧到源文件为止：站点配置一类是精确到行的改动，表单给的是「不用去找那一行」，而不是替理解配置这件事代劳。

构建

后台只管到源文件为止，落盘之后照常走命令行：

后台插入的代码块与站内既有写法同形，走同一套构建脚本转成高亮块，产物侧的比对只看判定标准：正文里真代码块的旧标记应为 0，高亮块数与源文件里的代码块总数一致，两类写法产出的高亮块计进同一条比对，不用分开算。讲这两种写法的文章会把旧标记当字面量写进代码围栏，那几处是示例文本，不计入这条判定。配置改完要重启 hexo server 才读得到新值。

比对不要用文件哈希。同一份源文件连续两次 clean 加 generate，产物原本并不逐字节相同：搜索索引的条目顺序跟着数据库遍历次序走，日期相同的文章之间每次排得不一样；侧栏「网站信息」控件的 data-lastPushDate 取的是构建时刻，每次构建都在动。这两处不是主题要表达的随机性，挂两个 hexo 钩子就能钉住：generateAfter 里把索引的 <entry> 段按 <url> 重排，改的是路由里那份字符串——挂在 hexo.route 上，hexo 实例没有 router 这个属性，写错就拿不到 routes；after_render:html 里把 data-lastPushDate 换成全站最新的文章更新时间。

钉过之后连续两次构建仍在变的只剩三类。一是相关推荐的候选取样，打分时给每篇候选挂一次 Math.random()，同分的候选取哪几篇、按什么顺序排，每次不同；二是标签页的标签云，顺序默认按 random 走（标签页的 front-matter 不写 orderby 就是随机），配色每个标签各取一次 Math.random()；这两类是主题自带的多样性，连着这个功能一起保留。第三类不算随机：一篇文章挂了多个同级分类或多个标签时，同级项之间没有稳定排序，front-matter 里的书写顺序在产物里不作保证，落在文章页元信息行、首页卡片和搜索索引条目里的先后因此每次构建可能不同。界面看不出来，也不为这一处多挂一层改写产物的钩子。

钉过之后的判定口径可以是三条：搜索索引按 url 升序、条目数与文章数对得上、文件可解析；带 data-lastPushDate 的页面取值只剩一个且等于按 front-matter 算出的最新更新时间；标题层级、高亮块、图片、引用块、表格这些按 <article> 与 .article-container 范围内逐项数，两次构建的计数一致。「整站哈希一致」这种断言看着严格，实际会把上面那三类差异当成回归。真要卡差异范围，可行的口径是差异文件只允许落在带相关推荐的文章页、首页分页、标签页与搜索索引这几处，别的页面一出差异就是回归。

跨文件门控的提示 真实站点上一条依赖不配合，代码块自动换行那一项的说明位是字典说明加一句「站点配置里高亮行号开着，这一项写了也不生效」，另一条依赖当前通得过就不出现；夹具上做两条同时不配合，说明位并成一句、改值保存后的提示整句带上这一句，全文件只有那一行变化、还原逐字节相同；把其中一条依赖从站点配置里删掉后说明位只剩不配合的那一条，缺值不算不配合
侧栏导航与概览 概览数量卡片与侧栏数量逐项相同，六档齐全；点卡片进对应表格，最近更新按日期取前八条、点首条进编辑；侧栏两项分组齐全，概览、集合列表、编辑页、配置清单与配置第二层分别高亮对应项；从概览点集合、从列表点「配置」、从清单点配置行都走真实跳转，地址栏跟着换，重载后仍停在同一页
列表表格 文章与草稿四列（标题、分类、标签、更新），页面、数据与模板三列（标题、路径、更新），资源四列（预览、文件名、路径、引用）；搜索与标签快筛同时生效时计数与行内容都对得上；点行进编辑

配置目录 目录顶层段数与表单顶层段数一致；搜索只出现在深层里的键能命中并跳到该行；清空搜索后滚动恢复当前段高亮；「到顶部」「到底部」直达两端；目录独立滚动，字号 14px、栏宽 240px；窄屏变整宽折叠块，默认收起、可展开

编辑器 工具条逐项、块级动作可逆、标题层级、表格增删行列、配图上传与粘贴、Markdown 预览形态、两种正文写法的保存等价——这些逐条跑过（细节见设计文档的验收表），改成通用实现后没有逐条重跑

已跑通

没跑过或没复测的部分，别当成已验证：概览在文章集合为空时的「还没有文章」空状态、分类选择器的两级联动、删除确认弹窗带引用数、封面上传与系统文件选择器的界面路径（同一通道只从接口与粘贴跑过）。配置页里补项行的点击与保存、只读那份的改动入口、门控那句说明与保存后的提示，这几处在浏览器里点过并取的是页面渲染出来的文本；其余界面点击类（按段折叠、选项焦点样式、列表项上下移的按钮态）没复测。「构建后主题读到 _data 的新值」「发布后产物有该文路由」「页面作为独立页渲染」这三条要跑构建比对，只做到源文件正确；中文标签、说明位、三段开关与下拉文案这几条的实测办法是把源码里那份字典和标签、控件函数原样取出来跑真实配置的解析结果，断言的是渲染出来的 HTML 字符串。「关闭 / 限制」两段与数字框的禁用联动、清空后不提交这两条也只验到渲染出的字符串与提交前的同值判定，浏览器里的点击没复测；node_modules/ 里主题自带配置的只读分支在本机没有对应目录，没跑过；主题默认配置那份文件读不到时整段不补的退回分支没跑过。深色模式下的版面观感（令牌值按站点深色产物配的，没做截图核对）；常驻场景（只用 nohup 起停过，没配任何进程守护）；把端口转发到另一台机器使用（只验证了本机连不上）；Markdown 与 HTML 块两种写法之间的互转（后台不做转换）；预览区与产物页面的逐像素对照（只做了结构逐项计数与保存后的产物比对）。

本站落地差异

通用口径落到这个站点上要拧的几处，都在这一节，前文按通用写法读即可：

  • 分类深度：站内最深两级，候选里出现 学习、生活 两个父分类与一条顶级分类 学生选课系统；早期版本把这两个父分类名内置在候选里，现在只从扫描来。
  • 说说：站内说说就是分类留空、带 说说 标签的文章，新建时点一下 说说 芯片、不选分类即可。为说说单开一套表和界面，等于把同一个数据存两处。
  • 正文形状：站内正文是 WordPress 导出再转换的块写法，判定扫到 wp-block-code 与 wp-block-table 就默认用块形状；侧栏那个芯片可以切到裸标签，切换记在浏览器本地。
  • 主题专属键：站内文章普遍带 top_img: false（图片横幅关掉），这一项不在表单里，靠原文区保留；abbrlink 由 hexo-abbrlink 维护，后台只保留不改写。
  • 编辑区与站点的样式对齐：站里正文基准 14px，主题对 h1 到 h6 只给 margin: 20px 0 14px、字重 700、颜色 #1f2d3d（深色态换成 rgba(255,255,255,0.9)），行高沿用容器的 2 倍，字号走浏览器默认比例；编辑区基准 16px，六级按 2em、1.5em、1.17em、1em、.83em、.67em 写死，不依赖浏览器默认值，两边比例一致。表头底色 rgba(153,169,191,0.1)、表头字重 700 居中、单元格内边距 6px 12px、表格圆角 5px、底部外边距 20px；行内代码底色 rgba(27,31,35,.05)、字色 #f47466、圆角 6px；代码块底色 #f6f8fa、字号 14px、圆角 6px。深色态随 prefers-color-scheme 换一组令牌。这些值是从构建产物里读出来的，改一处样式要同时核对站点产物，两边不一致时以站点为准。
  • 配图体积判定沿用 README 内容约定里配图入库那条，改的是服务端那一行常量。
  • 配置层真正用到的部分：站点配置与主题覆盖配置两份表单，主题覆盖那份的注释行数量与配置行相当，这也是写回必须只动一段的直接原因。
  • 本站的覆盖文件是整份副本：主题自带配置里 368 行带值控件的键，点路径在覆盖文件里都能对上，所以「根目录已覆盖」这一条标注在站内是全标，按叶子判与按段判给的是同一个集合；差别在同构夹具上量过。
  • 本站两份 YAML 都没写、由主题默认值补出来的键有 9 条，覆盖文件里多出来的就是这几行：nav.display_post_title、footer.nav、lazyload.native、rightside_config_animation、umami_analytics.script_name，加上 google_tag_manager 与 search.local_search.pagination 两组里的子键。主题那份 structured_data 在文件里是别的样子，只铺一行说明、不铺子项。
  • 根目录的 _config.landscape.yml 名字与 theme: butterfly 对不上，后台标 这一份不参与构建；这一份文件在本站点里没有任何读取路径，改这一份不进站点。
  • 代码块限高这一项要写成像素数或 false：主题在样式里把值当数用，写成布尔会让样式编译抛类型错，产物里两个样式文件变空、hexo g 却照样成功。界面按「关闭 / 限制」两段加一个整数框给这一项。
  • 代码块自动换行这一项被站点配置里的高亮行号门控：主题那条换行样式要同时满足行号关掉，本站站点配置里行号是开的，所以这一项改了看不出效果；要的是换行样式，得先改站点配置那一侧。
  • 部署链不在后台里：npx hexo clean && npx hexo g && npx hexo d 三步手工做，hexo d 是整站替换并强推产物仓库，推之前要先比对远端。
