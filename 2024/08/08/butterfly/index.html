升级建议

为了减少升级主题后带来的不便，请使用以下方法：

在 hexo 的根目录创建一个文件 _config.butterfly.yml，并把主题目录的 _config.yml 内容复制到 _config.butterfly.yml 去，以后只需要在 _config.butterfly.yml 进行配置就行。

注意：复制的是主题的 _config.yml ，而不是 hexo 的 _config.yml

注意： 不要把主题目录的 _config.yml 刪掉

注意： 以後只需要在 _config.butterfly.yml 进行配置就行。
如果使用了 _config.butterfly.yml， 配置主题的 _config.yml 将不会有效果。

Hexo自动合并主题中的 _config.yml 和 _config.butterfly.yml 里的配置，如果存在同名配置，会使用 _config.butterfly.yml 的配置，其优先度较高。

代码复制

主题支持代码复制功能，在 code_blocks 里用 copy 与 language 控制工具条上的复制按钮和语言标签。

代码高度限制

3.7.0 及以上支持，现在叫 code_blocks.height_limit。

可配置代码高度限制，超出的部分会隐藏，并显示展开按钮

注意：

  1. 单位是 px，直接添加数字，如 200
  2. 实际限制高度为 height_limit + 30 px，多增加 30px 限制，目的是避免代码高度只超出 height_limit 一点时，出现展开按钮，展开没内容。
  3. 不适用于隐藏后的代码块（ css 设置 display: none）。

代码框展开 / 关闭

修改主题配置文件_config.butterfly.yml。中的 code_blocks.shrink 属性

在默认情况下，代码框自动展开，可设置是否所有代码框都关闭状态，点击 > 可展开代码。

  • true 全部代码框不展开，需点击 > 打开
  • false 代码框展开，有 > 点击按钮
  • none 不显示 > 按钮

代码换行

在默认情况下，Hexo 在编译的时候不会实现代码自动换行。如果不希望在代码块的区域里有横向滚动条，可以考虑开启这个功能。

属性名现在是 code_blocks.word_wrap。

高亮从哪来

根配置里 syntax_highlighter: highlight.js，highlight 一节全用默认值：line_number true、auto_detect false、wrap true、hljs false、tab_replace 留空。这套只处理 Markdown 的围栏代码块。

正文里的代码块长成 <pre class="wp-block-code"><code> 这样：整段挤成一行，换行用 <br> 表示，Hexo 的高亮流程看不见它们，页面上就是一整块灰字。要高亮得先把它们转成主题认识的 figure.highlight。

转换放在 scripts/wp-code-highlight.js，注册 after_post_render，优先级 20。做三件事：解 HTML 实体（导入正文只用到 &nbsp; &gt; &lt; &#91; &amp;，仍按通用解码器写，命名与数字都认）、把 <br> 换回换行、按内容猜语言，最后交给 hexo-util 的 highlight() 出表格结构。行号与 wrap 跟着根配置读，产物的 class 名和主题原生围栏一致。

Hexo 的脚本目录有两处要留意。scripts/ 下的文件是被包进函数体执行的，module.exports 导出的函数不会有人调用，注册必须写成顶层语句、直接用注入进来的 hexo。文章正文只有 before_post_render 和 after_post_render 两个钩子，post_render 是模板层的，挂在它上面永远不触发。

语言用规则猜，没有再引检测库。顺序是先看首行签名（xml、sql、json、yaml），再看关键字，javascript 放在 java 前面，否则 new URL( 这类会把前端代码判成 Java；命令行前缀占比过半才认 bash。判语言之前先把零宽空格去掉，导入正文里混着 U+200B，不去掉会挡住 <?xml 这种首行特征，写进产物时保持原样。猜错只影响配色，不影响内容，认不准的一律给 plain，主题的角标把 plain 显示成 Code。

旧代码块全部转换，产物里 wp-block-code 归零。逐块比对过正文文本，唯一差异是 hexo-util 统一去掉的公共缩进。

token 配色补齐

转出来的 token 类名是 highlight.js 11 的，主题 _highlight/highlight/diff.styl 里写的是旧版类名，对不上的那批没有颜色，看着仍然像没高亮。主题侧不改，补进 inject.head 的 style，颜色取 light 色板原值。

params、meta、tag、attr、string、number、title、keyword、comment 主题本来就有颜色，不重复覆盖。punctuation 和 operator 留着不补，跟正文同色，这是 highlight.js 自己的默认行为。

token 色在构建期定死，深色模式不换一套，只有代码底色与正文色随主题走。浅色底 #f6f8fa 上最浅的是 built_in 与 title 的黄，深色底 #171717 上最弱的是补进去的紫，两组都是主题色板原值，没有另调。

高亮全部发生在构建期，运行时不多拉任何包。

可自行决定哪个项目需要显示，可决定位置，也可以设置不显示侧边栏。

修改主题配置文件 _config.butterfly.yml

这段就是本站文件里的实际取值，注释也是原样搬过来的。配置里找不到 runtimeshow 是正常的，5.5.3 没有这个键，页面上 #runtimeshow 只是那个计数元素的 id，开关是 card_webinfo 下的 runtime_date。

runtime_date 填站点起算日，本站取最早那篇文章的日期 2024-07-18 00:00:00。这个写法会被 YAML 直接解析成日期对象，模板再过 date_xml()，产物里输出 data-publishDate="2024-07-18T00:00:00.000Z"。日期写法认不出时不会静默跳过：构建在渲染侧栏时抛 RangeError: Invalid time value，出错点是 themes/butterfly/layout/includes/widget/index.pug 第 35 行，带侧栏的页面整张网站信息卡都不输出，构建日志里跟着 ERROR。改完在产物里 grep 一次 data-publishDate 确认取到了值。

天数由浏览器算，不在构建期固化：脚本取 data-publishDate 与当前时间做差、向下取整，后缀「天」来自语言文件里 aside.card_webinfo.runtime.unit。同一份产物在不同日期访问，数字自己变，不需要重新部署。触发条件写在主题的 js/main.js 里，GLOBAL_CONFIG.runtime 有值才会执行。

这张卡只在首页与页面侧栏渲染。文章页的侧栏走另一条分支，只有作者卡、目录、最新文章那几块，看不到运行天数，核对时以首页为准。

字数统计

要为 Butterfly 配上字数统计特性，你需要如下几个步骤:

  1. 打开 hexo 工作目录
  2. npm install hexo-wordcount --save
  3. 修改主题配置文件 _config.butterfly.yml

本站是 enable: false，正文页不显示字数和阅读时长，hexo-wordcount 也没装进依赖。要开就先装插件再改这一项，只改配置不装插件会报错。

v2.3.0 以上支持。

如想添加额外的 js/css/meta 等等东西，可以在 Inject 里添加，head (</head> 标签之前)， bottom (</body> 标签之前)。

本站配置差异清单

本站 _config.butterfly.yml 是把主题配置整份复制到根目录再改的，绝大多数键与默认一致。和主题官方 5.5.3 的 _config.yml 逐项比对，取值不同的键归成配置块就是下面这些。主题版本 butterfly 5.5.3，hexo 8.x。照着这张表改完，版面就和现站一致。

最后三行是从旧版本配置文件一路复制下来的残留。share 那两个列表仍然写 twitter，文末标签下方的分享按钮因此出现的是 Twitter 图标而不是官方 5.5.3 的 x，要跟上就把两处一起改。JSON-LD 由 structured_data 控制，模板里按布尔判断，老写法 true 照样输出，只是配不了 alternate_name 别名。CDN.version: false 只是不给第三方链接拼版本号查询串，资源全部本地之后没有影响。

比对基准要注意：主题目录里的 themes/butterfly/_config.yml 早前被覆盖成了站点配置的副本，直接拿它比对等于跟自己的另一份副本比，差异会偏少。要取官方默认值，用主题仓库里的那份：

两份文件行尾写法不同，直接 diff 会整片报差异，看具体键还是各自打开对照更省事；要精确比对，就把两份配置按叶子键展开取值再比。展开比对的口径是：两边都有且值不同的键、本站多出的键（menu、inject、CDN.option 那批），这两类就是上面那张表的范围；另有一批是 5.5.3 有、本站文件里压根没写的键，例如 nav.display_post_title、lazyload.native、rightside_config_animation、structured_data.enable，缺了就走主题默认，不影响版面，照着改的时候也不用补。

另外 footer.copyright 在这张表里没有，因为官方 5.5.3 默认就是对象；但被覆盖过的那份主题文件里写的是 copyright: true，从那种文件复制起点的话，这一处必须改回对象，否则页脚少一行，详见「页脚」一节。

顶部导航与 logo

滚动时顶栏不再消失。主题的滚动隐藏逻辑是给 #nav 换上一个 nav-fixed 类，配 .nav-fixed #nav { top: -60px } 把它推出视口；fixed: true 时另有 .fixed #nav { top: 0 }，优先级更高，正好把这条压掉，导航就一直贴着顶部。

菜单的写法是一行一项，页面名: 路径 || 图标类名；带 || 的键后面缩进一层就是分组，组名本身不可点。本站四个顶层项：首页、项目、文章、关于，生日页挂在「项目」组里。

静态资源本地化

主题的第三方库默认从 jsdelivr 取。站点所在网络取不到 jsdelivr，本站的访问环境也取不到，表现是缺图标、打字效果不跑、播放器整块不出现，而且不报错，页面照常生成。做法是把库放进 source/，再用 CDN.option 逐键覆盖，键名要和主题配置里注释的库名对上。

分享按钮这一项最容易漏。主题按 share.use: sharejs 去取 CDN.option.sharejs 与 sharejs_css 两个键，不覆盖就是每篇文章底部各挂一条 jsdelivr 的 css 和 js，取不到时按钮整块空白。图标字形在 share.min.css 里按 ../fonts/iconfont.woff2 这种相对路径引用，所以 assets/fonts/ 要和 assets/css/、assets/js/ 一起放，少放一层就是五个方框。三个目录的文件都从 npm 包 butterfly-extsrc 的 sharejs/dist 里取。

404 页的背景图 /img/error-page.png 由主题自带在 themes/butterfly/source/img/，构建时一起进 public/img/，不需要另备。

取这些库时别直连 CDN，用 npm 把包下载下来再挑需要的文件拷进 source/。

自检：构建产物里不该再有指向 jsdelivr 的样式或脚本标签。

没有输出说明该本地化的都本地化了。剩下的外部请求是运行时取数那几项，见「运行时外部依赖」。

背景音乐（APlayer 配 Meting）

两步：开注入开关，再把播放器容器放到底部注入里。

两项都要 true，每页才会加载 APlayer 与 Meting，主题取的是 CDN.option.aplayer_css、aplayer_js、meting_js 三个键，上一节已经指向本地文件。

播放器容器写在 inject.bottom 的第二项：

div 必须在 bottom，写在 head 时 body 还没开始解析，播放器找不到容器，页面上什么都不出。

data-api 要带模板参数，不能只写一个光秃秃的接口地址。Meting.min.js 做的是字符串替换，把 :server、:type、:id、:r 这些占位换成 div 上的 data-* 值；只写 https://api.injahow.cn/meting/，发出去的请求没有查询串，一条曲目都取不到。

主题默认的 api.i-meto.com 对 type=url 返回 404，播放列表和歌词是 200，所以整站换成 api.injahow.cn 这个源。曲目用网易云歌单：data-server="netease"、data-type="playlist"、data-id 填歌单号，其余 data-fixed 左下角悬浮、data-mini 迷你形态、data-order="random"、data-autoplay="false" 不自动播。

歌单里总有几首不可播的，APlayer 会自动跳过并弹一条提示，那条提示用样式收掉：.aplayer .aplayer-notice { display: none !important; }。

验证不能只看播放器画出来没有，要确认真的在出声：抓页面的资源请求，看有没有 m*.music.126.net 的音频分片进来，再看时间读数往前走。只看到播放条，可能是一首都没取到。

页脚

copyright 必须写成对象。模板读的是 copyright.enable 与 copyright.version，布尔值取不到这两项，「框架 Hexo | 主题 Butterfly」那一行不会出现，也不报错，很容易以为漏配了别的键。官方 5.5.3 的默认配置已经是对象，但站点里主题目录那份文件被覆盖成老版本的副本，写的是 copyright: true；从那种文件起手的，这一处要显式改回对象。

署名行是 © 2024 - 今年 By 61飞兔。两个值都不是写死的：起始年取 footer.owner.since，结束年取构建时的系统年份，名字取 hexo 根配置的 author。跨年之后重新构建，结束年会自己变。

页脚默认有一层白色渐变底，让整站背景色透不出来，用样式透明掉：

头图毛玻璃

顶图亮度压不住标题文字，又不想整块涂灰，就在蒙版上做轻微模糊。主题的蒙版选择器是 #page-header:not(.not-top-img)::before，它只在 mask.header: true 时才会编译出来；这一层是绝对定位、不设 z-index，画在头图之上、定位元素 #site-info 之下，正好是放 backdrop-filter 的位置，不会挡住标题和菜单。

模糊取 6px。再大画面就糊成一片、后面的内容看不见了，浅色模式亮度压到 .94、深色压到 .88，渐变三段透明度是 .16、.07、.20，目的是朦胧而不是遮挡。

两个前置条件：一是 mask.header 保持 true，关掉它这个选择器匹配不到任何元素，毛玻璃随之消失；二是页面要有顶图，没图时 #page-header 带 not-top-img 类，选择器同样不命中。

移动端：侧栏收起与个人信息折叠进抽屉

窄屏下右侧栏的收起按钮默认不显示，个人信息卡在页面里单独占一块，抽屉里又有一份头像和名字。做法是复用同一个按钮、把卡片搬进抽屉，全部写在 inject，不动主题源码。

样式部分（inject.head）：

媒体查询里三条各管一段：#rightside #hide-aside-btn 在窄屏显示出来，html.hide-aside .layout > #aside-content 让点按钮真的收得住，#aside-content > .card-info { display: none } 把原位那张卡收掉。后面两条规则给搬进抽屉的元素补样式，名字沿用主题的 --btn-bg 与 --btn-color 变量，深色模式下自动跟着换。

脚本部分（inject.bottom 第一项）：

克隆作者名插到抽屉头像下方，克隆「关注我」按钮插到站点数据下方，去掉原 id 避免和页面里的按钮重复。结尾把 menus.dataset.profileIn 置 1，脚本再跑一次就直接返回，不会搬出第二份。

抽屉里那三个数字是文章、分类、标签的计数，和侧栏的站点信息卡同源。窄屏断点用 900px，和主题自己的断点一致。

404 页面

开关打开后，主题在构建阶段生成 public/404.html，GitHub Pages 认这个文件名，访问不存在的路径就落到它。背景图主题自带，路径照抄即可。

标题会渲染成「站点名 | 站点名」两个重复段，是主题生成 404 时的既有行为，不是本地配置改坏的。

本地搜索

三处要同时到位，少一处只会搜不到东西，页面不报错：

  1. 装插件：npm i hexo-generator-searchdb
  2. hexo 根配置留 search 段，生成 search.xml
  3. 主题配置 search.use: local_search

配置以 GLOBAL_CONFIG.localSearch 输出到页面，不是 GLOBAL_CONFIG.search，写自检脚本时别读错键。

搜索框绑在导航那个内层 span 上，选择器是 #search-button > .search；点外层 #search-button 这个 div 没有反应，容易误判成搜索坏了。

结果区里会出现「共找到 N 篇文章」，命中词在摘要里高亮。

构建

改过 inject 要重启 server，页面级片段有缓存，光刷新看不到变化。只跑 hexo generate 不够，改主题配置后先 clean。scripts/ 下的脚本同样不在监听范围内，Hexo 的 watch 只覆盖 source 与 theme 两个 box，改完必须重启。

没有配的东西

为免照着改的时候多找，这些项本站是关着或留空的：友情链接页没建，source/_data/link.yml 不存在；social 留空；lightbox 留空，图片不能点大图；lazyload.enable: false；wordcount.enable: false；comments.use 留空，全站不显示评论模块；post_edit.enable: false。
